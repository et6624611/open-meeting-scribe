## 一、核心定位（全链路唯一底线）

**洞察板要回答的问题只有一个：针对这场会议暴露出的困境，真正的最优解决方案是什么。**

四条不可退让的约束：

1. **不是记录展示**。不表达参会人立场、谁要做什么、谁说了什么——这些已存在于原文、纪要、决策中，洞察板不重复。
2. **会议内容是输入，不是依据的全部**。AI 可以、且应当调用会议之外的知识、方法、行业实践来形成方案；会议文本只负责界定问题。
3. **产物是方案，不是判断的陈列**。v1 报告把洞察定义为「取舍、否定、共识、遗留」的判断层，仍然依附于会议叙述，本版作废该口径。判断可以作为方案的论证出现，但不是板的主体。
4. **AI 对方案负责**。板上呈现的是 AI 给出的解法路径：目标、方案结构、关键举措、预期效果与代价；用户通过共创修正方案，而不是修正记录。

一句话区分三种产物：

| 产物 | 回答 |
| --- | --- |
| 原文/纪要 | 会上发生了什么 |
| 决策/行动项 | 会上定了什么、谁执行 |
| **洞察板** | **面对这个困境，最优解是什么（哪怕会上没人想到）** |

## 二、问题诊断

### 2.1 现象

洞察板当前为 AI 直出自包含 HTML，实测产物为「会议概览 / 核心议题 / 关键洞察 / 延伸思考 / 待跟进」五段纯文字。图形化不明显，内容与纪要重复。

### 2.2 根因

| 层次 | 根因 |
| --- | --- |
| 定位层 | 从未定义洞察板是「方案生成器」。产品默认它是会议内容的再呈现，重复是必然 |
| 契约层 | 工具描述只约束安全与主题令牌，不约束产物形态；没有禁止立场复述、分工罗列、原文搬运 |
| 能力层 | 提示词要求 AI「总结/提炼」会议，而非「解题」。AI 被要求向后看（归纳会议），没被要求向前看（构造解法） |
| 信息层 | AI 只拿到会议文本，没被明确授权引入外部方法与实践，方案只能在发言内容里打转 |
| 呈现层 | 缺少方案型视觉编码；自由 HTML 由 AI 自选版式，它选择了成本最低的文字分节 |
| 架构层 | 9-23 已批准的阶段卡画布（InsightFlow）仍在代码库，但被挂在 fallback 分支，有 HTML 板后永不渲染 |

### 2.3 判断

渲染不是主要问题。**定位和契约不改变，任何画布都会退化成纪要的图形皮肤。** 本次优化必须在链路每一段都守住第一节的底线。

## 三、三场会议走查的发现

以新定位重新审视三场实例：当前产物（包括 v1 走查版画布）都停留在「归纳会议」，没有真正进入「解题」。差距如下：

| 会议 | 会议暴露出的困境 | v1 画布给的（仍是归纳） | 方案层应该给的（示例方向） |
| --- | --- | --- | --- |
| 主数据治理研讨会 | 12 万物料、无标准、无归口，清洗无从下手 | 「先治 5 万活跃物料」「增量阻断」等会议已有判断的整理 | 一套主数据治理方案：治理目标与分阶段路线、归口组织模型、编码标准框架、存量/增量闭环、衡量指标与里程碑 |
| 差旅报销预算讨论 | 多系统并行、控制逻辑不一致、主责不清 | 「用留存值」「入星瀚标准模块」等会上结论的罗列 | 预算管控整合方案：目标管控模型、系统整合架构（含自研/外购取舍）、数据主责与流向规则、迁移与切换步骤、风险兜底 |
| 《蜗居》叙事分析 | 困境不是剧情，而是「操控被浪漫化而观众不察」 | 手法拆解 + 「叙事在浪漫化」的判断 | 应对方案：媒介素养介入路径（如何识别、如何教育、如何在内容侧纠偏），可执行的识别框架与干预设计 |

三条规律：

1. **每场会都能抽象出一个真问题，但答案不在发言里**。会上的结论往往是局部的、妥协的、未完成的；方案层的价值正是补全它。
2. **短会更依赖 AI 的外部知识**。4.5 分钟的叙事分析，会议本身几乎不给解法，方案几乎全部来自 AI 调用领域知识。
3. **方案天然是结构化的，适合图形化**。目标→路径→举措→验证，本身就是阶段流；图形化是方案表达的内在需要，不是装饰。

## 四、优化建议

### 4.1 内容模型：板 = 一份解决方案

板的固定内容骨架（前端版式固定，AI 只填内容）：

1. **困境界定**：这场会真正要解决的问题是什么，一两句；不是议题罗列，是问题定义。
2. **方案目标**：解决后应达到的状态，可衡量。
3. **解决路径**：2–5 个阶段，从现状到目标；这是画布主视觉。
4. **关键举措**：每个阶段下的具体解法步骤，允许引入会议之外的方法、标准、实践。
5. **效果与代价**：预期收益、成本、风险与前提条件。
6. **待验证假设**：方案成立所依赖、但目前未被证实的前提。

禁止入板内容（底线清单）：

- 参会人立场、观点归属、谁说了什么；
- 责任人、分工、行动项（已由决策/待办承载）；
- 章节标题搬运、摘要复述、议题罗列、过程叙述；
- 对会议结论的单纯整理，除非作为「现状起点」出现在路径第一阶段。

### 4.2 能力模型：授权 AI 解题

- 提示词从「分析会议」改写为「界定困境 → 调用你的全部知识构造最优解」。
- 明确授权：可引入行业实践、标准框架、外部方法；会议文本用于界定问题与约束，不是答案边界。
- 要求方案给出**论证**：为什么这是最优解，关键取舍是什么；但论证以精炼形式附在举措/假设中，不写成文章。
- 方案必须区分「会上已有的」与「AI 补充的」吗？——不做视觉区分，避免板重新围绕会议组织；仅在单条需要回溯证据时用 seek 锚点关联原文。

### 4.3 载体：受约束 Mermaid，版式收回应用侧

- 共创产物从自由 HTML 改为受约束 Mermaid（沿用 brief §3：flowchart LR、2–5 个 subgraph、节点 ≤12、`@@毫秒` 锚点）。
- 阶段卡语义重定义为方案阶段：阶段标题 = 路径环节；阶段描述 = 该环节目标；芯片 = 关键举措/里程碑/假设。
- 前端 parseInsightFlow → InsightFlow 自绘，AI 不拥有版式。
- 困境、目标、效果代价、假设等非流程内容，由前端固定区块承载，AI 以约定字段提供，不允许自由铺文字墙。
- 降级链保留：Mermaid 解析失败 → 通用 MermaidDiagram，用户永远有图看。
- 存量 HTML 板保留只读过渡，提供「重做为方案画布」动作，不静默丢弃。

### 4.4 视觉编码：方案要素的五类语义

替代 v1 的「决策/共识/行动/遗留/分歧」会议状态编码：

| 芯片类型 | 语义 | 色彩令牌（建议） |
| --- | --- | --- |
| 举措 | 解法中的具体动作 | 蓝 --info |
| 里程碑 | 阶段完成标志 | 绿 --ok |
| 机制/规则 | 需建立的长期机制 | 紫 --purple |
| 假设 | 待验证前提 | 琥珀 --warn |
| 风险/代价 | 方案的成本与风险 | 红 --error |

- 左侧色条 + 文字标签双重编码，不单靠颜色。
- 阶段卡结构固定：阶段编号（前端生成）+ 路径环节标题（≤6 字）+ 环节目标（≤2 行）+ 芯片堆叠。

### 4.5 交互：克制，只有面板级入口

- 功能按钮只存在于洞察面板层（板头/空态的共创 CTA）。
- 画布内部不提供任何功能按钮，只保留悬停 tooltip；芯片点击维持 seekTo 回溯原文（仅在有锚点时）。
- 补充信息走芯片子行与 tooltip，不做弹层入口。
- 保留画布视口控件（适应/缩放/全屏）于左下角。

### 4.6 共创契约：工具提示词重写

- 工具名保留 `revise_insight_board`，参数从 `html` 改为 `mermaid` 加方案字段；单节共创改为单阶段（subgraph S<n>）替换，其余逐字节不动。
- 提示词必须写入：方案定位（解题而非归纳）、外部知识授权、底线清单（禁立场/分工/复述）、五类芯片标签约定、Mermaid 书写规范。
- 后端在落盘前做两道校验：
  1. 结构校验（阶段数、节点数、方向）；
  2. **底线校验**：检测产物是否退化为会议复述（如大量出现立场归属、议题罗列），命中即拒绝落盘并返回可读原因。
- 不合法不落盘。

## 五、全链路底线守卫

| 链路环节 | 守卫动作 |
| --- | --- |
| 数据输入 | 会议文本标注为「问题与约束来源」；同时向 AI 开放外部知识使用授权 |
| 系统提示词 | 首段即写明唯一任务 = 给最优解决方案；写入底线清单与正反例 |
| 模型输出 | 约定方案字段与受约束 Mermaid；要求举措可执行、假设显式标注 |
| 后端落盘 | 结构校验 + 底线校验，退化产物拒收；写入留痕 |
| API 契约 | 响应只暴露方案结构字段，不提供「按参会人/按原话」视图 |
| 前端呈现 | 版式固定为方案骨架；无立场、分工、原文复述区；画布内零功能按钮 |
| 共创循环 | 用户指令经提示词约束为「改方案」，防止共创把板拉回会议记录 |
| 验收 | 以第六节标准逐条核对，任一底线项不过即不通过 |

## 六、可观察验收标准

1. 打开任一有板任务，主视觉为方案阶段卡画布；首屏可见困境界定与方案目标。
2. 对照原文、纪要、决策逐项核查：板上无参会人立场、无责任人分工、无原话/章节/摘要复述。
3. 板的每个阶段都在回答「怎么从现状走到目标」；芯片全部为举措、里程碑、机制、假设、风险代价之一。
4. 板上至少存在一个会议中未出现、由 AI 引入的解法要素（方法、机制或路径）；若整场找不出，视为方案未生成。
5. 方案的关键前提以「假设」类型显式标注；风险与代价有独立区块，不是只写收益。
6. 五类芯片各有独立色条与文字标签；移除颜色后仍可凭标签区分。
7. 画布内部无任何功能按钮；悬停有 tooltip，带锚点芯片点击触发 seekTo。
8. 单阶段共创：目标阶段更新，其余逐字节不变，revision +1。
9. 退化输入（会议复述式 Mermaid）：后端底线校验拒绝落盘；或前端降级渲染，均无白屏、无 console 报错。
10. 旧 HTML 板任务：fallback 只读可见，并出现「重做为方案画布」入口。

## 七、风险与对策

| 风险 | 对策 |
| --- | --- |
| 模型仍习惯于归纳会议 | 底线校验硬拒 + 提示词正反例迭代；以验收 2、4 作为回归检查项 |
| 方案空泛、无可执行性 | 举措要求具体到机制/动作；里程碑必须可衡量；验收 3 卡口径 |
| 外部知识引入事实性错误 | 关键事实通过假设/风险类型标注不确定性；证据锚点链可回溯 |
| 短会问题界定不清，方案跑偏 | 困境界定区块先行，共创优先修正问题定义；允许「问题不明确」空态引导 |
| 模型不遵守 Mermaid 规范 | 通用 MermaidDiagram 降级；真实样本迭代提示词，达标线 80% |
| 参数改名导致写板同步漏改 | useBoardSync 与两引擎工具调用处统一更新并补测试 |
| 弹层定位复发吞导航 | 新增浮层走 popoverPosition 通道，遵守 rail 避让约定 |

## 八、结论

洞察面板的本质是 **AI 会议方案师**，不是会议记录的图形化。它以会议内容界定困境，以 AI 的全部知识构造最优解决方案，并对方案的路径、代价、假设负责。三场实例一致表明：真正的增量答案不在发言里，这正是洞察存在的理由。

建议按「方案定位、解题契约、方案型画布、全链路底线守卫」推进，技术上复用已就绪的 InsightFlow 链路，主要工作量在提示词重写、底线校验与呈现模型改造。
