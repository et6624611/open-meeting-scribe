# Plan: WP-H 超时与降级口径收口 + WP-I R9 分段增量上屏（引擎侧）

**Complexity:** Large — WP-I 含新模块（分段转写器）、引擎宿主协议语义修订（D-I1）、管线定稿策略变更（D-I2）与配置面扩展（D-I3）；WP-H 为 Small（两处行为修正 + 口径文案）。

## Goal

- **WP-H**：让本地引擎用户在导入/长会议音频转写时不因固定 180s 单请求超时整场失败，且设计内降级以非错误状态呈现、文案与实际支持时长一致。
- **WP-I**：让本地引擎用户在会议进行中即可看到按段定稿的转写文字（说话人整场一致、会中上屏＝会后定稿），单段失败不中断整场。

## Deliverables

### WP-H（分支 fix/local-engine-wph-20260924）

- 行为修正：`core/engine_host.py` 新增时长感知超时策略 `estimate_local_asr_timeout(duration_s)`（RTF 预算 0.5 s/s，下限 180s，支持上限 4h 常量可配置） → 长文件不再被固定 180s 掐死。
- 行为修正：`core/transcribe.py::_transcribe_local` 用 `get_audio_duration` 计算时长并传入上述超时；超过支持上限时报可分类错误（不发引擎请求，文件不丢） → 超时口径与实际支持时长一致、失败可恢复。
- 行为修正：`app/routers/record.py::_start_transcriber_bg` 对 `realtime_degraded_to_batch` 设计内降级改推 `type:"status"`（status=local_batch_mode）非错误状态声明；真实失败仍推 `type:"error"` → 降级不再红色报错刷屏。
- 文案：`docs/PRD-LOCAL-ENGINE.md` 补充本地批转写支持时长与超时口径；错误提示含支持上限信息 → 口径一致。

### WP-I（分支 task/local-engine-r9-20260924，基于 WP-H 分支）

- 语义修订（D-I1）：`core/engine_host.py` `request()/infer()` 拆两级——单请求可失败（超时不 stop 引擎，响应按 id 重同步、丢弃过期响应）；连续 N 次超时（`ENGINE_UNHEALTHY_CONSECUTIVE_TIMEOUTS`，默认 3，可配置）或进程死亡才判 unhealthy 重启。
- 新模块：`core/realtime_local_asr.py::LocalSegmentTranscriber` — VAD 静音驱动 + 最长时长兜底切段（可配置）、段级 `infer("asr")`、逐句 `diarizer.get_speaker()` 跨段说话人归属、每段闭合过 `apply_hotword_mappings`、单段失败只丢该段并推非错误提示、`stop()` 冲刷尾段。接口与 `RealtimeTranscriber` 鸭子兼容（start/feed_audio/stop/is_running）。
- 配置（D-I3）：`get_engine_config()["local"]["realtime_segments"]`：`enabled`（默认 false，REQ §8）、`min_segment_s`、`min_silence_s`、`max_segment_s`（临时默认 5/0.8/30，标注待真机 20s/60s 档实测校准，禁止写死为产品口径）。
- 接线：`app/routers/record.py` local+flag 开启时选用 LocalSegmentTranscriber，复用既有 `_on_sentence_end` → `sentence` 事件/全量转写缓冲；stop 时标记 `transcript_source_hint="local_incremental"`。
- 定稿策略（D-I2）：`core/pipeline_runner.py` 对 local_incremental 任务跳过 stage1 全量重跑，用 `_build_dialogue_from_realtime` 拼接即定稿 → stage2。
- `core/realtime_asr.py:222-233`：flag 开启时降级分支被增量路径取代；flag 关闭保持现状抛错（§8.1 待同步项随代码处置）。

**Out of scope:**
- 会中上屏 UI 增量改动（产品将追加派前端工程师）。
- 真机验收（AC-9 的 10/30/60 分钟真机会、P95 统计、AC-3 内存实测）——待 WP-G 引擎包 + QA 时间窗。
- D-I3 默认段长定值（需真机延迟分布）。
- WP-G 打包、ci-local-engine 缺陷。
- SECURITY.md:94 / API_CONTRACTS.md sentence 段级语义等文档同步（REQ §8.1「待同步」清单中非本包硬前置项，随验收批次）。

## Acceptance Criteria

| AC | 场景 | 断言 |
|---|---|---|
| AC-H1 | happy：本地模式 60 分钟文件 | `_transcribe_local` 传给 `infer` 的 timeout ≥ 1800s（=60min×0.5 预算），不再是 180 |
| AC-H2 | edge：超过支持上限（>4h）文件 | 抛可分类错误（category=audio、提示含上限），不发起引擎请求，音频文件保留 |
| AC-H3 | happy：local 录音启动降级 | 推送消息 `type=="status"` 且 `status=="local_batch_mode"`，不出现 `type=="error"`；非 local 模式真实启动失败仍推 `type=="error"` |
| AC-H4 | 回归：云路径零变化 | proxy/direct/cloud 的超时参数、消息类型行为与基线一致（既有测试全绿） |
| AC-I1 | happy：local+flag，喂含静音间隔的 PCM | 段按 VAD 静音/最长兜底闭合，句子经 on_sentence_end 以绝对毫秒时间戳逐段产出 |
| AC-I2 | error：单段 infer 抛 LocalEngineError/Timeout | 该段丢弃、引擎不 stop、推非错误 segment_skipped 提示、后续段继续出句 |
| AC-I3 | edge：连续 N 次段超时 | 第 N 次后引擎才 stop（N 可配置）；单次超时不 stop |
| AC-I4 | happy：同一说话人跨多段 | speaker_id 取自 diarizer 且整场稳定；FunASR 局部 spk 不直接跨段使用 |
| AC-I5 | happy：热词映射表非空 | 每段闭合句文本即完成替换（会中上屏文本含热词） |
| AC-I6 | D-I2 定稿一致性 | stop 后管线以 realtime_full_transcript 拼接为定稿，不触发整文件 `infer("asr")`；会中上屏文本＝定稿文本 |
| AC-I7 | 回归：flag 默认关 | 行为与现状一致（local 录音抛 realtime_degraded_to_batch → status 消息）；云路径全绿 |
| AC-I8 | 内存纪律 | 段闭合后音频缓冲即释放（不持有已闭合段 PCM）；diarizer/host 不因分段新增无界缓存 |
