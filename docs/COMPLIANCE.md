# 境外用户服务合规性分析

## 1. 业务模式

Open Meeting Scribe 以 SaaS 托管模式向境外用户提供订阅服务：

- 用户支付订阅费，按使用时长/用量消费
- 后端统一调用 ASR（语音识别）+ LLM（纪要生成）API
- 用户无需自行配置 API Key，不感知底层模型
- 音频数据经由 AI 模型处理（语音→文字→纪要）

## 2. 核心合规风险：音频 = 个人数据

音频录音包含人的声音，在几乎所有主流隐私法规中被视为**个人数据（Personal Data）**，因为声音可识别特定个人（声纹）。

### 当前数据流向（国内站百炼）

```
境外用户音频 → 服务器 → 国内百炼 ASR（数据落地中国）→ 国内 Qwen LLM（数据落地中国）
```

数据实际进入中国境内的阿里云服务器进行处理。

## 3. 各地区法规对照

| 法规 | 适用地区 | 核心要求 | 国内站百炼合规性 |
|------|---------|---------|----------------|
| **GDPR** | 欧盟/EEA + 英国 | 个人数据不得传出欧盟，除非接收国有"充分性认定" | ❌ 不合规 — 中国不在欧盟充分性认定名单 |
| **CCPA/CPRA** | 美国加州 | 需披露数据去向，用户有权拒绝跨境传输 | ⚠️ 有风险 — 需明确告知且用户可拒绝 |
| **PDPA** | 新加坡 | 跨境传输需确保接收方提供同等保护 | ⚠️ 有风险 — 需合同条款保障 |
| **PIPA** | 日本 | 向第三方提供需事先同意 | ⚠️ 有风险 — 需用户明确授权 |
| **APPI** | 韩国 | 类似 GDPR 的跨境传输限制 | ⚠️ 有风险 |

### GDPR 重点分析（最严格，罚款最重）

- 音频数据传入中国 = **跨境数据传输**（Art. 44-49）
- 中国**没有**欧盟的"充分性认定"（Adequacy Decision）
- 理论上需要：签署 SCC（标准合同条款）+ TIA（传输影响评估）
- 即使签了 SCC，监管机构**也可能认定**中国环境下数据保护不足
- 违规罚款上限：**全球年营收 4% 或 2000 万欧元**（取高者）

## 4. 应对方案

### 路径 1：用户明确同意（灰色地带，仅限早期验证）

在产品中明确告知用户：

> "您的音频数据将由位于中国的 AI 服务进行处理"

用户勾选同意后使用。

**法律依据**：GDPR Art. 49(1)(a) — 数据主体的明确同意

**限制**：
- 不能作为常规数据传输机制，仅为**临时例外**
- 用户可随时撤回同意
- 数据量大、频率高时，监管机构可能不认可

**适用阶段**：用户量 < 100 人的验证阶段

### 路径 2：百炼国际站 + 境外节点（推荐，合规正解）

```
境外用户音频 → 境外服务器 → 百炼新加坡/法兰克福节点 → 数据不出境
```

| 节点 | 数据所在地 | 合规覆盖 |
|------|-----------|---------|
| 新加坡 (ap-southeast-1) | 新加坡 | PDPA |
| 法兰克福 (eu-central-1) | 欧盟境内 | GDPR ✅ |
| 弗吉尼亚 (us-east-1) | 美国境内 | CCPA ✅ |

**国际站 API 域名**：
- LLM：`https://dashscope-intl.aliyuncs.com/compatible-mode/v1`
- ASR WebSocket：`wss://dashscope-intl.aliyuncs.com/api-ws/v1/inference`
- 业务空间专属域名（推荐生产环境）：`https://{WorkspaceId}.{region}.maas.aliyuncs.com`

**注册方式**：通过阿里云国际站授权渠道商邀请注册，无需境外手机号。

### 路径 3：混合架构（长期最优）

```
国内用户 → 国内服务器 → 国内站百炼（dashscope.aliyuncs.com）
境外用户 → 境外服务器 → 国际站百炼（dashscope-intl.aliyuncs.com）
```

两套 API Key、两套服务器、同一套代码。`asr-proxy` 和 LLM 配置已支持 `base_url` 配置，改造成本可控。

## 5. 执行路线图

### 阶段 1：验证期（当前）

- [x] 使用国内站百炼 + 路径 1（用户明确同意）
- [ ] 在产品中加入数据处理告知 + 同意勾选
- [ ] 编写隐私政策（Privacy Policy），明确说明数据处理方、数据所在地、数据类型
- [ ] 风险等级：低（用户量小，被监管关注的概率极低）

### 阶段 2：有付费用户后（月活 > 50）

- [ ] 通过渠道商注册百炼国际站
- [ ] 部署境外服务器（新加坡轻量服务器 ~$5/月）
- [ ] 境外用户请求走国际站新加坡节点
- [ ] 编写完整的 Privacy Policy + Terms of Service（英文版）
- [ ] 实现用户数据删除功能（GDPR Art. 17 被遗忘权）
- [ ] 成本增加：约 $5-10/月 服务器 + 国际站 API 费用

### 阶段 3：规模化

- [ ] 实施路径 3 混合架构
- [ ] 按用户地区自动路由请求到对应节点
- [ ] 欧盟用户强制走法兰克福节点
- [ ] 签署 SCC（标准合同条款）
- [ ] 进行 TIA（传输影响评估）
- [ ] 考虑 appoint EU Representative（GDPR Art. 27）

## 6. 技术侧需要实现的合规功能

| 功能 | 法规依据 | 优先级 |
|------|---------|--------|
| 数据处理同意勾选 | GDPR Art. 6 | P0（上线前必须） |
| 隐私政策页面 | GDPR Art. 13-14 | P0 |
| 用户数据导出 | GDPR Art. 20 数据可携带权 | P1 |
| 用户数据删除 | GDPR Art. 17 被遗忘权 | P1 |
| 数据处理记录（审计日志） | GDPR Art. 30 | P1 |
| Cookie 同意 | ePrivacy Directive | P2 |
| DPO 指定 | GDPR Art. 37（大规模处理时） | P3 |

## 7. 关键结论

1. **国内站百炼处理境外用户音频在 GDPR 等法规下不合规** — 这是确定的
2. **百炼国际站提供合规解法** — 新加坡/法兰克福/弗吉尼亚节点，数据不出境
3. **注册国际站不需要境外手机号** — 通过渠道商邀请注册即可
4. **架构改造成本可控** — `asr-proxy` 已支持 `base_url` 配置
5. **现阶段可先用"明确同意"过渡** — 但不可作为长期方案
6. **优先实现隐私政策和同意机制** — 这是无论哪个阶段都必须有的
