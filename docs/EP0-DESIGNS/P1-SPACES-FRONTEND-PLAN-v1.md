## 0. 架构总决策（三条，先钉死）

1. **空间=运行时上下文，不是路由前缀**。详情/副本类页面走既有 `taskId` 路由（副本行独立 id，服务端按成员权解析，天然空间无关）；仅"列表+词表+变更/成员"消费空间上下文。**私有↔团队不复制路由表**，避免 URL 深链出现"团队 id 泄露到分享链接"的越权面。团队专属两页新路由：`/changes`、`/members`（私有空间访问重定向 /library，复用 enterpriseRedirect 守卫模式）。
2. **切换即失效单点**：新增 `stores/space.ts` 与 origins.ts `setActiveUser` 同构——切换空间=一个函数清空全部服务端态缓存（contexts 列表缓存、assets 快照、决策列表）并重载；当前空间 id 不进 localStorage 之外的任何持久层（防串数据面比 P0 更大）。最近所在空间存 `oms.u.<uid>.last_space`（scopedKey 纪律，登出 purge 覆盖）。
3. **权限呈现=角色单源推导**：`my_role` 只从 teams 列表端点取（§9.1 契约直用），组件一律消费 `spaceStore.myRole`（computed），任何视图不得自行判断"我能不能编辑"；只读=不渲染不解释（规格 §3，与 P0 3b 裁决同尺）。

### WP-2 公开链·私有面（预估 2.5d）
- `PublishToTeamDialog.vue` 新建：团队多选下拉（已公开团队置灰"已公开到该团队"、归档团队不列出）；内容勾选区（纪要/决策逐条/笔记/术语默认不带）；**"不会出现"区=LockedPrivacyBlock 第五行挂点，恒显示不可勾选**；副本语义如实文案（规格 §4.2 全文为文案基线）。
- 入口两处：库卡片菜单 + 详情页纪要页签（决策卡片逐条"公开此决策"）。
- 原件呈现：卡片角标"已公开到 N 个团队"→点开团队列表+逐团队"撤回公开"（二次确认文案规格逐字）；**徽标体系不动**——原件恒"个人·仅你可见"，"已公开到"是分享状态非可见性（防歧义双轨呈现）。
- API：`POST publish {team_id}`（纪要/决策两 payload）+ 撤回端点，单源进 teams.ts。

验收断言：多发=每团队独立发布态可辨；撤回互不影响；弹窗锁定行逐字=§8 基准（QA B5 目检第 6 面在此批起生效）。

### WP-5 diff 冲突组件（预估 2.5d，规格 §6 下限形态=交付形态）
- `ConflictDiffDialog.vue` 新建 + `utils/paraDiff.ts`（段落级对齐）：
  - 切段=空行分隔（Markdown block 级）；对齐=段落序列 LCS 动态规划（段落数量级 <200，O(n·m) 无性能问题，**零新依赖**）；两序列同文段=透传灰显，异/缺段=黄标。
  - 交互：左=服务器新版/右=我的修改；每差异段"用这边的"单选；顶部"全用他们的/全用我的"快捷；输出合并文本。
  - 状态机：编辑中 draft → PUT → 409{current_rev, latest_full}（**冻结必含项①，联调首查项**）→ 弹窗装载两版 → 取舍 → merged → 新 Idempotency-Key + If-Match=current_rev 重推 → 成功关窗/再 409 重入循环。取消=弃稿装载新版（规格逐字语义）。
  - 短文本参数化（词表单文本框并排退化，同组件 props 开关）。
- 复用 `snapshotConflictRev` 装载层（后端双确认在案）；绝不静默覆盖；冲突不记留痕（P1 裁）。

验收断言：双端同编必出弹窗不出覆盖；合并结果=所选段落集合逐段可验；词表冲突退化形态生效。

## 3. 红线与风险登记

1. **个人版零变化**：全部改动包逐批 `npm run build`（默认=个人）+ diff dist 抽查；edition 分流点复查。
2. **local plane 零感知**：空间概念不进 origins/assistant/sync 任何代码；录音面门控维持。
3. **词表纪律**：禁"企业空间/企业资产/公司层"字样=用户可见面零出现（TB 文案扫）；"副本"不进文案；禁词 grep 进每批验收。
4. **存储纪律**：新增键仅两个，均 scopedKey（last_space、team_toast 已读），登出 purge 覆盖，播报注明。
5. **风险①**：diff 组件段落对齐是纯前端新算法——WP-5 先行单测（paraDiff 对 12 组样本文本断言），不占联调窗口。
6. **风险②**：契约 v1.0 正式版本号后端尚未播报；本方案按 v1.0-draft+冻结令两条必含项编写，若正式基线有出入以差异最小方式吸收、不重排批次。
7. **风险③**：`/changes`、`/members` 在只读成员的入口隐藏但直链可达（列表页只读可见=规格 §1.2 变更记录全员可见，无问题）；`/members` 非管理员直链=403 分态文案，不渲染内容。
