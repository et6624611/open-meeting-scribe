## 1. 空间切换信息架构

### 1.1 切换器（侧栏顶部，常驻）
```
┌─────────────────────────┐
│ ▾ 当前空间：私有空间      │ ← 点击展开下拉
│   （小锁徽标·仅你可见）   │
├─────────────────────────┤
│ 我的团队（下拉内列出）     │
│  ✓ 私有空间              │
│  · 产品组          [管理员]│
│  · 华东项目组       [可编辑]│
│  · 外部顾问小组     [只读] │
│  ─────────────────       │
│  + 新建团队              │
└─────────────────────────┘
```
- 下拉中每个团队右侧标注**我在该团队的角色**（管理员/可编辑/只读）；角色是"我的属性"，必须显性——这是只读成员理解"为什么我不能改"的第一入口。
- 团队多于 6 个时下拉内搜索框出现。
- 切换空间 = 切换整个工作区上下文（会议库/热词/发言人/设置内容全部随空间重载）；当前空间名常驻切换器按钮，任何页面都能回答"我现在在看谁的、什么权限下的内容"——这是本规格最重要的一条防事故设计。
- 数据源：teams 列表端点（§9）。新成员被拉入团队时列表变化，不需刷新页面外的动作。

### 1.2 各空间导航归属
| 入口 | 私有空间 | 团队空间 |
| --- | --- | --- |
| 我的会议 | ✓（P0 原样） | 团队公开面（§5） |
| 热词 | 只读窗口（P0 原样） | 团队共享词表（编辑权随角色） |
| 发言人别名 | 只读窗口（P0 原样） | 只读（P1 维持；是否共享词表级=待裁决 U4） |
| 变更记录 | — | ✓（全员可见，§7） |
| 成员管理 | — | 管理员可见 ✓ |
| 设置（助手/数据位置） | ✓ | 不出现（设备属性属个人，不随空间） |

- 规则：设置两分区不进团队空间——录音助手是"这台电脑"的设备属性，与"谁的内容"无关。

## 2. 建团队与选成员

### 成员（任何员工）看到什么
1. 下拉底部"新建团队"→ 弹窗：团队名（必填，一次输入框即可）→ 下一步"选择成员"：搜索企业用户列表（管理员建的活跃账号），多选；**自己默认在内（角色=管理员，不可取消）**。
2. 点"创建"→ 进入新团队空间空态页："团队建好了。把您的纪要或决策公开进来，同事就能看到。"
3. 被拉入他人团队：无审批流（v0.2：管理员邀请即入），该团队出现在其下拉，角色按配置；首次进入该团队时顶部一次性轻提示"您已被 X 加入团队「Y」（角色：只读）"，确认即散不留守踪。

### 管理员（指团队管理员，非实例管理员）看到什么
- 团队空间"成员管理"：列表=姓名/角色/加入时间；操作=添加成员、改角色（只读↔可编辑）、移出成员、**转让管理员**（选一人，二次确认）、**归档团队**（输入团队名确认；裁决④=归档非毁灭：文案如实"归档后您和同事仍可查看历史内容，但不再接受新的公开和编辑"；归档团队在切换器保留列出并带"已归档"标记，全员只读，不再接受写入；彻底删除能力归管理台整包删除治理口径，P2 细化）。
- 移出成员：其已公开到团队的内容**保留**（副本归团队时间线），历史留痕不删——信任模型里"发出去的话不因离场而消失"。

## 3. 三档角色的界面差异（一句话版）

| 角色 | 看 | 改 | 管 |
| --- | --- | --- | --- |
| 只读 | 全部内容 | 无任何编辑控件（不渲染，非灰态按钮） | 无 |
| 可编辑 | 全部内容 | 团队副本内容（纪要/决策条目/笔记/词表） | 无 |
| 管理员 | 全部内容 | 同可编辑 | +成员/角色/改名/转让/解散 |

- 只读成员进团队：切换器角色标注 + 页头一行中性说明"您在这个团队是只读成员；如需编辑内容，请联系团队管理员 X"（给出口不制造缺失感，修复 P0"藏而不释"同类问题）。
- 可编辑成员无"成员管理"入口（不渲染不解释）。

## 4. "公开到团队"动作

### 4.1 入口与粒度
- **纪要级**：私有会议库卡片菜单 + 详情页纪要页签"公开到团队…"。
- **决策条目级**：详情页决策卡片每条带"公开此决策到团队…"（v0.1 设计：一条决策常常比整篇纪要更值得共享）。
- **笔记/词表**：随纪要级弹窗内勾选项出现（见 4.2）。

### 4.2 公开确认弹窗（核心承诺面）
```
公开到团队
公开给：[团队下拉（多选，裁决①=原件可同时公开到多个团队；每团队独立发布态可辨——
  已公开到的团队在下拉内置灰标注"已公开到该团队"（重复选择无效），撤回入口按团队独立（§4.3），
  归档团队不出现在选择列表（裁决④不再接受新写入）]▾

将公开：
 ☑ 纪要   ☑ 决策（本场共 4 条，可逐条调整）   ☑ 笔记   ☐ 术语（默认不带）

不会出现（永远留在您的设备）：
    录音音频 · 逐字转写

公开后：团队能看到这份副本；您私有空间里的原件不受影响，
同事的修改也不会改动您的原件。您可以随时撤回。

[取消]  [确认公开]
```
- "不会出现"区**恒显示、不可勾选、无开关**——把裁决 5 变成用户看得见的事实，这是团队空间第五锁定表面的挂点（文案见 §8）。
- 公开动作=创建副本（后端语义），弹窗文案已按"副本两条时间线"如实表述（"同事的修改也不会改动您的原件"）——防"共享文档"误解。

### 4.3 公开后的呈现
- 私有原件卡片角标：小锁+"已公开到 N 个团队"（点开=团队列表+逐个"撤回公开"按钮；撤回二次确认，文案"撤回后团队不再看到这份内容，您的原件不受影响"）。
- 私有原件永远保持"个人·仅你可见"徽标语义（私有空间列表不出现"团队"字样的可见性徽标——"已公开到"是**分享状态**，不是可见性变更；两套信息分开呈现，防歧义）。

## 5. 团队内容视图（成员进团队看到什么）

### 5.1 团队"我的会议"位=团队公开面
- 卡片列表：公开到本团队的纪要副本（标题+公开人+公开时间+来源会议名弱显）；空态："还没有人公开内容。您可以把自己的纪要或决策公开进来。"
- 卡片点开=只读详情（同 A 项版式语言，Tab：纪要/决策/笔记/**洞察**——裁决⑤洞察板随副本进团队，复用 P0 insights_html 字段与桥接渲染，入口语义与个人版一致）；可编辑角色起编辑按钮+diff 冲突流（§6）；只读角色无编辑控件。洞察 Tab 仅当副本含 insights_html 时出现（无内容不渲染空页签，沿用 P0 纪律）。
- Web 端无音频回放、无逐字转写 Tab——数据边界在团队面同样结构性不可达（后端复制器白名单，前端无该 Tab 即如实，不需要"已隐藏"提示）。

### 5.2 团队决策视图（承接"决策面板"回归）
- 独立页签/入口"决策"：本团队全部已公开决策的聚合列表，卡片沿用 P0 决策样式（左描边+状态 pill），按公开时间倒序，支持按来源会议分组/筛选+关键词搜索。
- 每条卡片：决策文本、状态、公开人、来源会议链接（只链到团队副本，**不链私有原件**——防越权穿透）；已撤回的不在此列表（§7）。
- 删除权（裁决③）：管理员与可编辑成员对**任何人**公开的决策条目有"删除"操作（卡片菜单内，二次确认"删除后同事不再看到这条决策，可在变更记录中恢复"）；只读成员无删除项。删除写入变更记录并带"恢复"操作（管理员/可编辑可见恢复按钮）——删除权的信任对价是全员可见的留痕，本条与 Q4 裁决互为实现。
- 此视图是"项目/决策面板变少"债的偿还面之一（T-002 B 项）：P1 首版做决策聚合；"项目=跨会议归组"能力列 U5（不默认承诺）。

### 5.3 团队共享词表
- 热词团队面：有编辑权者=可增删词条的列表；只读者=纯列表。一行指引沿用 P0 范式："这里的词表团队共享，修改会在同事的转写中逐步生效。"（生效机制=助手侧合成，后端 ② 裁决范围，界面不解释技术细节）

## 6. 编辑冲突与 diff（FE 点名决策项，定"下限形态"为 P1 交付形态）

- 触发：后推者 409（服务端已有新版）。P1 形态**不做三方合并**，定为：
  1. 冲突弹窗："同事在您编辑期间修改了这份内容。请对照两边，选择保留哪个版本，或手动合并后再保存。"
  2. **左右并排视图**：左=服务器最新版，右=我的未保存修改；差异段落黄色标注（段落级对比即可，不做词级）；每段差异给"用这边的"单选，顶部给"全部用他们的/全部用我的"快捷。
  3. 用户取舍后生成合并文本 → 以新 rev 重推（复用 P0 幂等/If-Match 协议）；取消=放弃我的修改并装载新版。
- 纪律：绝不静默覆盖（后端已裁 last-writer-wins 不用于团队面）；冲突弹窗出现即记一条变更留痕"编辑冲突已解决 by X"可选，P1 不记（保持操作记录粒度简单）。
- 词表等短文本冲突退化为单文本框并排（同一组件参数化），不另做交互。

## 7. "已撤回"与变更记录（Q1/Q4 落地）

- 撤回/解散后：团队面内容即时消失；资产层保留标记记录**零界面**（全站不出现"企业空间/企业资产/已归档到公司"等字样——QA TB 硬断言）。
- 变更记录视图（团队空间内，全员可见）：轻量倒序列表=时间/操作人头像+姓名/操作（公开了《X》、修改了《Y》的纪要、撤回了《Z》、删除了某条决策、移除了成员…），分页加载，无审批无跳转复杂度。只读角色可见但无操作。删除类条目对管理员/可编辑角色附"恢复"按钮（裁决③的回滚面）；恢复本身也是一条新留痕。此列表的"撤回了"条目即 Q1"已撤回"的唯一前台呈现形态——状态在留痕里，不在内容上。

## 8. 文案与锁定表面

- **第五锁定表面（产品经理契约冻结令逐字定稿，B5 基准，与 P0 三行卡同级断言）**：§4.2 弹窗"不会出现（永远留在您的设备）：录音音频 · 逐字转写"所在承诺块：
  > 公开到团队的内容里不会包含录音音频和逐字转写，它们永远只保存在您的设备上。
- 挂点仅此一处（公开确认弹窗）；变更记录、团队首页等出现同义表述时用普通文案，不并入 B5 逐字断言范围——防锁定面无限扩张（冻结令确认采纳本纪律）。
- 目检表面计数终版（随冻结令更新）：P0 五表面（登录/激活/同意卡/数据位置表/初始化向导）+ 本面 = **六表面**；FE 随 lockedCopy.ts 单源扩行，禁手抄纪律沿用。
- 全站词表纪律（P1 增量）：禁"企业空间/企业资产/公司层"任何用户可见字样；"云端"禁令沿用；"副本"不进用户文案（用"团队看到的这份/您的原件"）。

## 9. 对后端契约的字段依赖（供契约冻结会核对）

1. `GET /api/v1/context/teams`：[{team_id, name, my_role(admin/editor/viewer), member_count?}]——切换器直用。
2. 发布/撤回端点支持**单条决策粒度**与纪要粒度两种 payload（§4.1）。
3. 团队面 409 响应含 current_rev + 最新全文快照（§6 并排视图需拉新旧两版全文）。
4. 变更记录列表端点：分页、操作类型枚举（公开/修改/撤回/成员变更/转让/解散）。
5. 用户搜索端点（建团队选成员用；管理台已有列表端点可复用则注明）。
6. "我已被加入团队"轻提示不需未读态端点（首访判断即可），如后端愿给 joined_at 更准。
