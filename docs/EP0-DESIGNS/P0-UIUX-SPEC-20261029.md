## 0. P0 用户心智模型（一句话）

企业版 P0 = 公司里装了一台"会议文字柜"（服务器），每位员工有自己的账号抽屉；
录音仍然发生在员工自己这台机器上，只有写完的文字放进文字柜。
界面上所有设计都要让用户随时能回答两个问题：**"我的录音在哪？"**（本地）和**"我的文字在哪？"**（公司服务器）。

## 1. 登录 / 用户空间

### 员工看到什么
1. 打开公司给的网址 → **登录页**：账号 + 密码。账号由管理员创建，首次登录强制设置/修改自己的密码。
2. 登录成功 → 进入 **"我的空间"**：就是现在软件里的熟悉界面（录音、纪要库、项目、决策流、热词、发言人、设置），全部内容默认只有本人可见。
3. 顶栏右侧固定出现 **头像菜单**：设置、"我的数据在哪"、退出登录；管理员额外多一项"进入管理台"。

### 界面规则
- 未登录访问任何功能 URL → 统一重定向登录页，不弹空白页或报错。
- 会话过期（掉线）→ 顶部提示条"登录已过期，请重新登录"，正在编辑的内容本地暂存不丢。
- 登录页需明确一句话说明（隐私预期锚点）：
  > "你在这里使用的服务由公司内网服务器提供。录音保存在你自己的电脑上，会议文字保存在公司服务器上，同事无法看到你的会议内容。"

## 2. 本地数据目录设置（用户端 Settings）

前提事实（前端评审已确认）：浏览器本身不录音，录音由本机的"录音助手"（本地引擎）完成。因此用户端 Settings 需要两个新分区：

### 分区 A：「本机录音助手」
- 状态卡：本机是否已连接录音助手（绿/灰）。
  - 已连接：显示版本号、数据目录路径、剩余磁盘空间。
  - 未连接（例如在同事电脑或手机上打开网页）：显示引导页——"这台电脑还没有安装录音助手"，提供下载地址 + 配对码引导流程；同时明确"不安装也可以：你可以正常查看和编辑已有会议文字，只是不能在这台电脑上新开录音"。
- 操作：修改本地数据目录（含"移动已有文件"二次确认）、查看用量、清理。

### 分区 B：「数据位置」（P0 隐私指示核心）
静态说明页 + 图标化三行表，回答"什么存在哪里"：

| 内容 | 存放位置 |
| --- | --- |
| 会议录音音频 | 只在你这台电脑 |
| 密钥、声纹识别信息 | 只在你这台电脑 |
| 会议文字（转写、纪要、决策流、笔记、术语） | 公司服务器 |

- 该分区只读、无开关（P0 上云行为不可关闭，与裁决一致）；文案避免"云端"字样，统一说"公司服务器"。
- 词表约束：与个人版"联网模式"词表区隔——企业版不使用"联网/离线"描述上下文存储，避免与 2026-09-26 定稿的设置页信息架构冲突。

## 3. 上传知情同意流程

### 首次触发
员工第一次完成会议并生成纪要时，弹一次 **知情同意卡**（仅首次，可回看）：
- 三行大白话：即将上传什么（本次会议的文字结果）、不会上传什么（录音、密钥、声纹）、存在哪里（公司内网服务器）。
- 按钮：「知道了，继续」/「查看数据位置」。
- 此后每一张纪要卡片上常驻 **数据位置徽标**（见 §5），作为持续告知，替代每次弹窗。

### 断网/重传的用户感知
离线时文字暂存在本机待传队列，界面显示"X 条文字待同步"，恢复后自动重传；不报错、不丢字。状态文案用"待同步到公司服务器"，不用"上传失败"红色告警（P0 简化：仅状态栏提示）。

## 4. 管理台 MVP 信息架构（管理员看到什么）

### 入口与边界
- 管理台是**独立网址**（如 http(s)://公司服务器地址/admin），与员工界面完全分离；员工端不出现任何管理功能入口。
- 管理员本人用会议功能时就是普通员工身份，两边界面不混排。
- 首个管理员来自 DevOps 的"管理员初始化向导"（装机时设定的那一个人）。

### 页面结构（P0 共 3 页 + 1 引导）
1. **概览**：服务运行状态、用户数、磁盘用量、最近同步动态。顶部大开关：企业服务的启用/停用（停用后员工端显示"服务已暂停，请联系管理员"，本地数据不受影响）。
2. **用户管理**：
   - 列表：姓名、账号、状态（正常/已停用）、创建时间、上次使用。
   - 操作：新建用户（姓名+账号+初始密码，或生成邀请码由员工自助设密码）、重置密码、停用/启用。
   - 每个操作有二次确认，停用用户不影响其已存数据。
3. **数据与备份**（只读为主）：服务器文字数据总览、指向 DevOps 备份流程的说明卡（P0 不做界面化备份操作）。
4. **老数据归属说明页**（一次性）：见 §6。

### 管理台不承担（P0 明确不做）
审计日志界面、团队/企业上下文管理、配额管理——留给 P1/P2，避免首版做重。

## 5. 上下文可见性徽标（P0 仅样式预留）

统一徽标组件，三态定义一次到位，P0 只渲染"个人"：
- **个人**（P0 唯一实际态）：小锁图标 + "仅你可见"，出现在纪要/决策/项目卡片与详情页。
- **团队**（P1）：图标预留、不出现在界面；数据字段随接口返回但固定为 personal。
- **企业**（P2）：同上预留。

规则：徽标是**数据属性**的展示，不是页面分类导航；P0 不出现"团队/企业"任何文字，防止用户误以为已有共享功能（前端评审确认 P0 视图层不改，本预留与此一致）。

## 6. 存量数据迁移的用户体验（账号 13373013103）

- 该手机号账号首次登录企业版时，显示一次性卡片："检测到你过去在这台电脑上的会议资料，已归入你的账号。"列数量摘要（N 场会议、M 条纪要）。
- 迁移是归属确认而非上传动作：文字按既定边界同步到公司服务器，音频仍留原机——卡片需重申这一点。
- 其他员工账号首次登录：空状态页"还没有会议，点击开始记录第一场会议"。

## 待产品经理裁决的产品问题

1. **建号通知方式**：管理员创建账号后，初始密码如何到达员工——线下当面给、打印条、还是 P0 就做"邀请码"（管理员生成码，员工自助首次设密码）？我建议 P0 用邀请码，省掉管理员传密码的麻烦，但需与后端账号流程对齐。
2. **"无录音助手"设备的定位**：员工在没有本地引擎的电脑/手机打开网页时，P0 是否接受"只能看和编辑文字、不能录音"的只读+编辑形态？（我建议接受，并在引导页把话术定死；这决定移动浏览器兼容是否进 P0 工作量。）
3. **老数据归属卡**：13373013103 首登时的迁移说明卡是"告知即过"，还是需要该账号点一次"确认归属"？涉及后端迁移是否需要用户侧回执。
4. **企业服务停用开关的可见范围**：管理员停用服务后，员工端是登录页就拦截，还是登录后可见"服务已暂停"页？影响前端会话处理排序。
5. **知情同意卡文案终审**：§3 三行文案是隐私承诺的对外口径，建议由产品经理定稿并同步 QA 的数据出境白名单措辞，保证 UI 声明与抓包清单逐字一致。
