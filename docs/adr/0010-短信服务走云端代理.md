# ADR-0010：短信服务走云端代理，密钥不落地

- **状态**：已接受（2026-09-07）
- **关联**：ROADMAP P1「短信代理改造」

## 背景

原方案中，阿里云 AccessKey（`ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET`）明文存储在客户端 `.env` 文件中。Windows 打包后这些密钥随安装包分发，存在泄露风险。

## 决策

将短信发送与核验请求改为 HTTP 调用云端代理，代理持有阿里云 AccessKey 并调用 PNVS SDK。客户端不再存储任何阿里云密钥。

### 通信协议

- 客户端 → 代理：POST JSON，附带 `X-SMS-Timestamp`（Unix 秒）和 `X-SMS-Sign`（HMAC-SHA256(token, timestamp)）
- 代理校验签名 + 时间戳（TTL 5 分钟防重放），再调用阿里云 PNVS SDK
- 代理 → 客户端：JSON 响应 `{"success": true/false, "message": "...", "expire_minutes": 5}`

### 端点

| 路径 | 方法 | 请求体 | 用途 |
|------|------|--------|------|
| `/sms/send` | POST | `{"phone": "13800138000"}` | 发送验证码 |
| `/sms/verify` | POST | `{"phone": "...", "code": "123456"}` | 核验验证码 |

### 环境变量变更

移除：
- `ALIBABA_CLOUD_ACCESS_KEY_ID`
- `ALIBABA_CLOUD_ACCESS_KEY_SECRET`
- `SMS_SIGN_NAME`、`SMS_TEMPLATE_CODE`、`SMS_TEMPLATE_PARAM`、`SMS_CODE_TYPE`、`SMS_CODE_LENGTH`

新增：
- `SMS_PROXY_URL`（默认值通过环境变量配置）
- `SMS_PROXY_TOKEN`（共享密钥，与代理端一致）

## 后果

- **正面**：AccessKey 不再随安装包分发，泄露面大幅缩小；客户端依赖减少（无需 `alibabacloud_dypnsapi20170525` SDK）
- **负面**：短信功能依赖代理服务器可用性；需确保代理端签名校验逻辑与客户端一致
- **代理端已实现**：`sms-proxy/` 目录包含完整 FastAPI 服务，含签名校验、PNVS SDK 调用、systemd 部署脚本，详见 `sms-proxy/README.md`
