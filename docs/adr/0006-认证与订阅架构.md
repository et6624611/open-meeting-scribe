# ADR-0006 认证与授权架构：OAuth + License Key

- 状态：Superseded（由 ADR-0015 取代，商业订阅部分不再实施）
- 日期：2026-09-06
- 相关：MISSION.md、docs/ARCHITECTURE.md、core/users.py

> **定位说明**：本项目为个人开发者维护的开源软件，不提供商业订阅服务。原文档中的「团队订阅」「付费」「微信支付/支付宝」等内容不再实施，保留本文档仅作为 OAuth 认证与 License 架构的技术参考。

## 背景

项目定位为「本地软件驱动 + 云端 AI」的开源工具。当前无任何认证机制，所有数据存储在本地 JSON 文件中，假设单用户本地使用。

随着产品演进，需要引入：
1. **用户身份** — 开源模式下用户如何注册/登录
2. **协作授权** — 团队协作功能需要开发者授权
3. **功能门控** — 区分基础功能和协作功能

约束条件：
- 开源模式，代码公开可见 → 不适合依赖联网验证的订阅方案
- 本地数据·云端智能定位 → 认证/验证应尽量本地完成
- 用户群体以国内为主 → 支付需支持微信/支付宝
- 弹性团队规模 → 架构预留扩展空间

## 选项

### 个人认证

1. **用户名/密码自管理** — 优点=无外部依赖；缺点=需管理密码哈希、忘记密码、安全防护，复杂度高
2. **仅第三方 OAuth（GitHub / Google / 微信）** — 优点=零密码管理、用户熟悉、安全性高；缺点=依赖第三方平台、需注册应用
3. **手机号+验证码** — 优点=国内用户习惯；缺点=需短信服务商、有成本、合规要求

### 团队订阅验证

1. **联网验证（SaaS 模式）** — 优点=实时控制；缺点=与开源离线定位冲突、需维护验证服务器
2. **License Key 离线验证（签名验签）** — 优点=离线可用、无需服务器、适合开源模式；缺点=无法远程吊销、需管理密钥对
3. **混合模式（首次联网 + 离线缓存）** — 优点=兼顾安全和离线；缺点=复杂度高、用户体验不一致

### 支付

1. **Stripe（国际）** — 优点=集成简单；缺点=国内用户不友好
2. **微信支付 + 支付宝** — 优点=国内主流；缺点=需企业资质、对接流程较长
3. **爱发电/Buy Me a Coffee** — 优点=零门槛；缺点=无法自动化发放

## 决定

**个人认证**：选项 2 — 仅第三方 OAuth（GitHub / Google / 微信）。不管理密码，不引入手机号验证。

**团队授权**：选项 2 — License Key 离线验证。使用 Ed25519 签名，软件内置公钥，本地验签即可激活。

**支付**：不适用。本项目不提供商业订阅服务，微信支付/支付宝接入已取消。

### License 数据（data/licenses.json）

```json
{
  "license": {
    "key": "OMSK-XXXX-XXXX-XXXX",
    "team_name": "团队名称",
    "max_members": 10,
    "features": ["sharing", "admin", "analytics"],
    "issued_at": "2026-09-06T00:00:00Z",
    "expires_at": "2027-09-06T00:00:00Z",
    "signature": "Ed25519签名（Base64）"
  },
  "public_key": "Ed25519公钥（Hex）"
}
```

## License Key 格式

```
原始 JSON:
{
  "tid": "team-uuid",
  "name": "团队名",
  "members": 10,
  "features": ["sharing", "admin"],
  "iat": 1725580800,
  "exp": 1757116800
}

签名流程:
1. JSON 序列化 → 计算 Ed25519 签名
2. 拼接: JSON_bytes + signature_bytes
3. Base32 编码 → 分段插入 "OMSK-" 前缀
4. 最终格式: OMSK-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX
```

验证流程（纯本地）：
1. 解码 Base32 → 分离 JSON 和签名
2. 用内置公钥验签
3. 检查过期时间
4. 加载功能列表

## 后果

- 正面：
  - 零密码管理，安全性高
  - License 离线验证，符合开源/本地数据·云端智能定位
  - 基础功能完整，不阉割核心能力
  - 协作功能弹性扩展，架构预留充分

- 负面 / 代价：
  - 需在三个 OAuth 平台注册应用（一次性工作）
  - License 私钥需妥善保管，泄露后可伪造 License
  - 无法远程吊销 License（可接受：最坏情况是发布新版本更换公钥）
  - 微信/支付宝商户接入已取消（不提供商业订阅）

- 后续需注意：
  - 密钥对生成后，私钥只存在开发者本地，公钥编译进软件
  - 考虑未来是否需要 License 吊销机制（CRL 列表）
  - 微信支付/支付宝接入已取消，个人开发者不提供商业订阅服务
  - 开源社区贡献者 fork 后需自行注册 OAuth 应用
