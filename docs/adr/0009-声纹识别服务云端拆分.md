# ADR-0009 声纹识别服务云端拆分

- 状态：Implemented（已部署并启用）
- 日期：2026-09-06
- 实施：2026-09-06（voiceprint-service/ 目录，本地验证通过）
- 部署：2026-09-06（云端服务器，systemd 自启，防火墙已开放）
- 主项目切换：2026-09-06（去掉本地 CAM++，纯云端 + MFCC 降级）
- 相关：docs/ARCHITECTURE.md、core/voiceprint.py、core/diarization.py、core/embedding_provider.py、ADR-0005、ADR-0006

## 背景

当前声纹识别（CAM++ 192 维神经声纹嵌入）完全在本地运行，依赖 `torch`（~543 MB）+ `torchaudio`（~4 MB）+ 28 MB 模型权重，是软件包体中最大的单项依赖（占总包体 60%+）。

声纹识别的计算链路分两段：
1. **embedding 提取**（CAM++ 推理）— 中等计算量，需要 torch
2. **聚类 / 匹配**（余弦相似度 / 匈牙利算法）— 轻量，仅需 numpy + scipy

embedding 提取是纯函数：输入音频信号 → 输出 192 维向量，天然适合服务化。聚类/匹配逻辑依赖本地状态（注册表、实时缓冲区），应保留在本地。

同时，项目已有认证与授权架构（ADR-0006），声纹识别可作为授权用户的云端可选能力。

**目标**：
- 将 embedding 提取从软件本体拆出，定义为云端 API 服务
- 本地代码通过抽象接口调用，支持云端/MFCC 降级切换
- 为 Windows 精简版打包铺路（不含 torch → 包体从 ~600 MB 降至 ~200 MB）

## 拆分范围分析

声纹识别在当前代码中有两条独立链路：

| 链路 | 模块 | 调用频率 | 延迟敏感度 | 拆分策略 |
|------|------|----------|------------|----------|
| **实时聚类** | `core/diarization.py` | 每 1.25 秒一次 | 高（影响实时标注） | **保留本地** |
| **批处理识别** | `core/voiceprint.py` | 转写完成后一次 | 低（已等了转写时间） | **可上云** |
| **说话人估算** | `app/store.py` | 文件上传时一次 | 低 | **可上云** |

### 实时链路保留本地的理由

`diarization.py` 每 1.25 秒提取一次 embedding，对延迟敏感：
- 本地 CAM++ 推理：~50-100 ms
- 云端 HTTP 往返：~100-500 ms（国内网络）
- 累积延迟会导致说话人标注与 ASR 句子时间戳错位

且 `diarization.py` 已有 MFCC 降级方案（不依赖 torch），当 torch 不可用时自动降级为 14 维 MFCC 特征，功能可用（精度略低）。

### 批处理链路上云的理由

`voiceprint.py` 在转写完成后批量提取每位说话人的 embedding（通常 2-6 人），对延迟不敏感：
- 用户已经等待了转写时间（几十秒到几分钟）
- 多人的 embedding 可以批量发送，减少请求次数
- 音频片段可以通过 DashScope 临时存储 URL 传递，避免大文件上传

## 选项

### 拆分粒度

1. **方案 A：只上云 embedding 提取（推荐）** —— 本地保留聚类/匹配逻辑，云端只做 CAM++ 推理。改动最小，隐私最好（注册表不离开本地），包体缩减显著。
2. **方案 B：整条声纹管线上云** —— 本地只传音频文件，云端返回完整的说话人识别结果。本地彻底去掉 torch + sklearn，但需上传完整音频到云端，隐私敏感用户有顾虑，且注册表管理逻辑需要重新设计。

### 云端数据传输方式

1. **直接上传音频文件（multipart）** —— 优点=简单直接；缺点=每段音频都要上传，带宽浪费
2. **通过 DashScope 临时存储 URL 中转** —— 优点=复用现有上传链路，音频已在 DashScope 生态内；缺点=需额外传递 URL
3. **Base64 内嵌** —— 优点=单次请求；缺点=体积膨胀 33%，不推荐

### 本地降级策略

1. **无降级，云端不可用则声纹功能不可用** —— 简单但体验差
2. **降级为 MFCC 14 维特征** —— 复用 diarization.py 已有的 MFCC 提取代码，精度较低但功能可用
3. **提示用户安装 torch 本地依赖** —— 灵活但增加用户负担

## 决定

**拆分粒度**：方案 A — 只上云 embedding 提取。

**数据传输**：方式 2 — 通过 DashScope 临时存储 URL 中转（批处理场景音频已在本地归一化，可直接上传；或直接 multipart 上传小片段，因为批处理场景每段通常 < 3 分钟）。

**本地降级**：方式 2 — 云端不可用时降级为 MFCC 14 维特征（复用 `diarization.py` 已有的 MFCC 提取代码）。

**默认模式**：本地数据·云端智能。`settings.json` 中配置 `voiceprint.provider: "cloud"` 且设置了云端 API Key 后才启用云端模式。

> **2026-09-07 更新**：实时链路（`diarization.py`）已切换为通过 `embedding_provider` 提取嵌入（云端 CAM++ 192 维优先，MFCC 14 维降级）。用户接受 100-500ms 网络延迟换取分离准确率大幅提升。阈值根据 provider 维度自动选择（CAM++: 匹配 0.55 / 合并 0.65；MFCC: 匹配 0.65 / 合并 0.52）。

> **2026-09-07 更新（用户偏好驱动）**：实时声纹方案切换改为用户偏好 + 授权状态驱动。新增 `core/users.py` 的 `should_use_local_diarization()` 和 `core/diarization.py` 的 `create_realtime_diarizer()` 工厂函数。规则：体验期用户（free）/ 未登录强制本地 MFCC；扩展授权用户（personal/pro/team）默认云端 CAM++，可通过 `prefs.local_diarization` 切换回本地 MFCC。API 端点：`GET/POST /api/user/prefs` 读写偏好，`GET /api/settings` 返回 `diarization` 节（含 `can_toggle` 标志）。

```python
from typing import Protocol, Optional
import numpy as np

class EmbeddingProvider(Protocol):
    """声纹嵌入提取提供者接口"""
    
    @property
    def dim(self) -> int:
        """嵌入向量维度"""
        ...
    
    @property
    def model_version(self) -> str:
        """模型版本标识"""
        ...
    
    def extract(
        self,
        audio: np.ndarray,
        sample_rate: int = 16000,
    ) -> Optional[np.ndarray]:
        """
        从音频信号提取声纹嵌入向量。
        
        Args:
            audio: float32 音频信号，值域 [-1, 1]
            sample_rate: 采样率
        
        Returns:
            嵌入向量（已 L2 归一化），或 None（提取失败）
        """
        ...
    
    def extract_from_pcm(
        self,
        pcm_bytes: bytes,
        sample_rate: int = 16000,
    ) -> Optional[np.ndarray]:
        """从 PCM 16bit 字节数据提取嵌入"""
        ...
    
    def is_available(self) -> bool:
        """检查提供者是否可用（模型已加载 / 网络可达）"""
        ...
```

### Provider 选择逻辑

```python
# core/embedding_provider.py

_provider: EmbeddingProvider | None = None

def get_embedding_provider() -> EmbeddingProvider:
    """
    获取当前生效的 embedding 提供者。
    
    选择优先级：
      1. 云端 CloudEmbeddingProvider（settings.json 配置 + 服务可达）
      2. 兜底 MfccFallbackProvider（14 维，精度较低但零依赖）
    """
    global _provider
    if _provider is not None:
        return _provider
    
    settings = _load_voiceprint_settings()
    
    # 1. 云端优先
    if settings.get("provider") in ("cloud", "auto") and settings.get("cloud", {}).get("api_key"):
        try:
            _provider = CloudEmbeddingProvider(
                base_url=settings["cloud"]["base_url"],
                api_key=settings["cloud"]["api_key"],
            )
            if _provider.is_available():
                logger.info("[声纹] 使用云端 embedding 提供者")
                return _provider
        except Exception as e:
            logger.warning(f"[声纹] 云端提供者不可用: {e}")
    
    # 2. MFCC 兜底
    logger.warning("[声纹] 云端不可用，降级为 MFCC 14 维特征")
    _provider = MfccFallbackProvider()
    return _provider
```

## 云端 API 契约（已部署）

部署地址：通过环境变量 `VOICEPRINT_BASE_URL` 配置
API Key：通过环境变量 `VOICEPRINT_API_KEY` 配置
服务管理：systemd（voiceprint-service），开机自启

### 端点

```
POST /api/v1/voiceprint/embedding
```

### 请求

```
Headers:
  Authorization: Bearer <VOICEPRINT_API_KEY>
  Content-Type: application/json

Body:
{
  "audio": "<base64 编码的 WAV 数据（16kHz 单声道）>",
  "sample_rate": 16000,
  "model": "campplus-v1"
}
```

> 使用 base64 内嵌而非 multipart，因为批处理场景每段音频通常 < 3 分钟（< 30 MB），base64 膨胀后可接受。若后续发现带宽瓶颈，可改为 multipart 或 URL 中转。

### 响应

```json
{
  "embedding": [0.012, -0.034, ...],
  "dim": 192,
  "model_version": "campplus-v1",
  "duration_sec": 45.2,
  "usage": {
    "credits_consumed": 1
  }
}
```

### 错误码

| HTTP 状态码 | 含义 | 客户端处理 |
|-------------|------|------------|
| 400 | 音频格式错误 / 时长不足 | 记录日志，跳过该说话人 |
| 401 | API Key 无效 | 提示用户检查配置 |
| 402 | 额度不足 | 提示用户充值，降级为 MFCC |
| 429 | 请求频率超限 | 指数退避重试 |
| 500 | 服务端错误 | 降级为 MFCC |

| 字段 | 值 | 说明 |
|------|-----|------|
| `provider` | `"local"` / `"cloud"` / `"auto"` | 嵌入提取提供者 |

- `"local"`：强制使用本地 CAM++（需要 torch）
- `"cloud"`：强制使用云端（需要 API Key）
- `"auto"`（默认）：优先云端，不可用时回退本地，再不可用时降级 MFCC

## model_version 兼容

云端 CAM++ 使用相同的预训练权重，输出与本地一致的 192 维 embedding。但为区分来源，云端 `model_version` 设为 `"cam++-v1-cloud"`。

注册表匹配规则调整：
- 本地 provider 提取的 embedding（`cam++-v1`）可与云端提取的（`cam++-v1-cloud`）互相匹配
- 在 `match_voiceprint_detail()` 中，将 `cam++-v1` 和 `cam++-v1-cloud` 视为兼容版本

```python
COMPATIBLE_VERSIONS = {
    "cam++-v1": {"cam++-v1", "cam++-v1-cloud"},
    "cam++-v1-cloud": {"cam++-v1", "cam++-v1-cloud"},
}
```

## 后果

- 正面：
  - Windows 精简版包体从 ~600 MB 降至 ~200 MB（-60%）
  - 声纹识别成为授权用户的可选云端能力，与 ADR-0006 的 License 体系衔接
  - 代码架构更清晰：embedding 提取与聚类/匹配解耦
  - 主项目彻底去掉 torch 依赖，启动更快、包体更小
  - 现有功能完全不受影响（云端不可用时自动降级 MFCC）

- 负面 / 代价：
  - 新增一层抽象，代码复杂度略增
  - 云端模式下批处理有网络延迟（但用户已在等转写，可接受）
  - 需要维护云端服务（当前单台轻量机器，成本低）
  - MFCC 降级模式下声纹识别精度下降（14 维 vs 192 维）
  - 实时说话人分离从 CAM++ 192 维降级为 MFCC 14 维，区分度降低

- 后续需注意：
  - 云端服务的 SLA 和可用性监控
  - embedding 数据在传输过程中的安全（当前 HTTP，后续应升级为 HTTPS）
  - 云端 CAM++ 模型版本升级时，需确保与本地输出版本一致
  - 计量计费逻辑需与 ADR-0006 的 License 体系对齐
