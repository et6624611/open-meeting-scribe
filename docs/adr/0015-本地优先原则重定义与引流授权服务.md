# ADR-0015 本地优先原则重定义与引流授权服务

> ✏️ 编者注：本 ADR 标题中的「本地优先」已在正文中重定义为「本地数据·云端智能」，文件名保留原文作为历史记录。

- 状态：Accepted
- 日期：2026-09-12
- 相关：[MISSION.md](../../MISSION.md)、[ADR-0006](0006-认证与订阅架构.md)、[ADR-0014](0014-移动端走Webhook消息流.md)、[core/auth.py](../../core/auth.py)、[core/users.py](../../core/users.py)、[docs/design/MOBILE_DESIGN.md](../design/MOBILE_DESIGN.md)

## 背景

### 表述歧义

v1 阶段 `MISSION.md` 中「本地优先」的表述为「核心链路优先本地运行，LLM 等重算力环节支持云端兜底」，`AGENTS.md` 禁区里也提到「不改 MISSION『本地优先』的长期定位（云只是 v1 捷径）」。

这套表述在实施中引发两类误读：

1. **误读为「纯离线」**：外部贡献者以为项目要拒绝所有云端 API，与现状（DashScope ASR/LLM、sms-proxy、asr-proxy、voiceprint-service 都走云端）矛盾
2. **误读为「主服务本地锁死」**：在讨论移动端方案（[ADR-0014](0014-移动端走Webhook消息流.md)）时，「本地无公网 IP」被作为硬约束排除了企业微信智能机器人等需要公网回调的选项，但实际用户诉求是「**数据文件在本地**」，主服务位置本可灵活

### 体验授权机制

项目方计划引入**体验授权机制**：

- 用户在项目方官网注册 → 获得一定时长的免费软件体验
- 体验期：走项目方共享的 proxy（现有 asr-proxy / sms-proxy / voiceprint-service），无需自配 API Key
- 体验期结束：用户自行配置 DashScope Key、Telegram Bot Token 等，转为「自持模式」

此模式与 [ADR-0006](0006-认证与订阅架构.md) 提出的「离线 License Key 授权」不冲突，是**并存的两种授权机制**，覆盖不同用户群体（个人试用 vs 协作授权）。

> **注**：本项目为个人开发者维护的开源软件，不提供商业订阅服务。体验期配额由开发者根据 API 费用承担能力自行设定。

## 选项

### 「本地数据·云端智能」的语义

1. **保持模糊表述** —— 优点=无需改动；缺点=持续引发误读，外部贡献者对齐成本高
2. **改为「纯本地」** —— 优点=语义强硬；缺点=与现状（走云 API）矛盾，需推翻 v1 全部代码
3. **重定义为「数据主权本地 + 计算能力云端」** —— 优点=贴合现状，边界清晰；缺点=需同步多篇文档

### 体验授权服务形态

1. **纯离线 License**（复用 ADR-0006） —— 优点=无需运营服务器；缺点=无法动态管理试用时长
2. **纯在线授权** —— 优点=试用时长可控；缺点=需运营轻量服务
3. **在线授权 + 离线降级** —— 优点=试用体验在线管控，自持后可离线运行；缺点=实现复杂度中等

## 决定

### 「本地数据·云端智能」重定义

采用**选项 3**：「本地数据·云端智能」（原「本地优先」）= **用户数据主权归属本地**，而非「离线运行」。具体分层：

| 层 | 位置 | 内容 |
|---|---|---|
| **数据层** | 用户本地设备 | 录音文件（`data/recordings/`）、纪要（`data/output/`）、tasks/settings/users.json 等全部业务数据 |
| **主服务层** | 用户本地设备 | FastAPI 主服务（`127.0.0.1:8000`）、Vue 前端、`core/*` 管线逻辑 |
| **计算能力层** | 云端 API | DashScope ASR/LLM、项目方共享 proxy、用户自配的消息通道（Telegram / 企业微信） |
| **授权层**（新增） | 项目方云端 | License 校验、试用期管理；**不承载任何业务数据** |

**关键约束**：
- 用户业务数据**永不落地**到项目方服务器
- 主服务默认在本地；用户如自愿部署到自己的云（跨设备访问场景），项目方不提供官方部署服务，也不禁止
- 授权服务只做 License 校验与试用期配额管理，不参与业务流程

### 体验授权服务

采用**选项 3**：在线授权 + 离线降级。

- **在线阶段**（试用期）：主服务启动时向项目方授权服务验 License，通过则允许调用共享 proxy
- **离线阶段**（自持模式）：用户自配 API Key 后，主服务不再依赖项目方授权服务，可完全离线运行（License 缓存到本地，Ed25519 签名验签）
- **与 ADR-0006 关系**：ADR-0006 的离线 Ed25519 License 保留作为**协作授权**方案（未来实施）；本 ADR 的在线授权专用于**个人试用**

### 数据模型（预览）

`data/users.json` 用户对象新增字段：

```json
{
  "id": "uuid",
  "license": {
    "type": "trial|self_hosted|collaboration",
    "issued_at": "2026-09-12T00:00:00Z",
    "expires_at": "2026-10-12T00:00:00Z",
    "signature": "Ed25519签名（离线降级用）"
  }
}
```

具体字段与校验流程在 v2 立项时另出 `docs/design/LICENSE_DESIGN.md` 详定。

## 后果

### 正面

- **表述清晰**：外部贡献者一眼看懂「本地数据·云端智能」的边界，不再与云 API 使用矛盾
- **体验授权可行**：体验授权机制为项目方提供试用管理方式，同时保持开源承诺
- **移动端方案约束不变**：ADR-0014 的「本地无公网 IP」默认约束依然成立，企业微信智能机器人回调仍不推荐；但用户如自愿将主服务部署到自己的云，可解锁该能力（作为可选路径，非默认）
- **与 ADR-0006 并存**：离线授权（协作场景）与在线授权（个人试用）覆盖不同场景，互不冲突

### 负面 / 代价

- **文档同步成本**：`MISSION.md`、`AGENTS.md`、`docs/design/MOBILE_DESIGN.md` 均需修订表述（在本 ADR 通过时同步完成）
- **授权服务运营**：项目方需运营一个轻量授权服务（注册 / License 签发 / 试用期管理），虽不承载业务数据但仍是新增运维项
- **试用期共享 proxy 成本**：项目方承担试用期用户的 ASR/LLM 调用费用，需设置配额上限防滥用

### 后续需注意

- 体验授权服务的具体实施（API 契约、License 格式、试用期配额、防滥用策略）在 v2 立项时另出 `docs/design/LICENSE_DESIGN.md`
- ADR-0006 状态保持 `Superseded`，等体验层跑通后再评估协作授权是否推进
- 用户如选择将主服务部署到自己的云（跨设备访问场景），需自行解决公网 IP / 内网穿透 / HTTPS 证书问题，项目方不提供官方部署服务
- 现有 asr-proxy / sms-proxy / voiceprint-service 在试用期作为共享资源，需在部署文档中标注「试用期共享」与「用户自持」两种模式的切换方式
