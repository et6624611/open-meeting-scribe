# ADR-0006 实时说话人分离方案选型

- 状态：Accepted
- 日期：2026-09-03
- 相关：core/diarization.py、app/server.py、requirements.txt
- 依赖：ADR-0001（v1 纯云方案）、ADR-0004（实时转写模型）

## 背景

实时转写使用 `qwen-audio-3.0-asr-flash-streaming`，该模型不支持说话人分离（无 speaker_id 返回）。录音过程中所有句子都显示为同一说话人，用户无法区分谁在说话。

千问 App 等竞品在实时录音过程中就能区分不同发言人，需要实现类似能力。

## 选项

### 1. 本地声纹聚类（MFCC + 余弦相似度）

**原理**：
- 从 PCM 音频流中提取 MFCC 特征（13 维）+ 能量特征
- 每 2 秒提取一次，基于余弦相似度实时聚类
- 相似度高于阈值 → 归入已知说话人；否则创建新说话人

**优势**：
- 零云端依赖，纯本地计算
- 轻量级（numpy + scipy，无大模型）
- 实现简单，开发周期短
- 符合 v1 纯云方案定位（声纹模型很小，不算"大模型"）

**劣势**：
- 基于声学特征的启发式方法，准确率低于神经声纹模型
- 适合 2-4 人会议；人数过多或音色相近时可能误判
- 需要每人至少说 2 秒才能建立可靠档案

**结论**：v1 采用。

### 2. 神经声纹模型（resemblyzer / WeSpeaker）

**原理**：
- 使用预训练的神经网络提取声纹 embedding（256 维或更高）
- embedding 空间中专一性更强，聚类准确率更高

**优势**：
- 准确率高，能区分音色相近的说话人
- 工业级方案，千问等竞品可能采用

**劣势**：
- resemblyzer 依赖 webrtcvad、librosa，Python 3.14 兼容性未知
- WeSpeaker 需本地部署模型（~1GB），与 v1 纯云方案冲突
- 实现复杂度高，开发周期长

**结论**：v2 考虑，v1 不采用。

### 3. 云端流式说话人分离 API

**原理**：
- 使用支持流式说话人分离的云端 API（如 DashScope 未来可能推出的模型）

**优势**：
- 准确率最高
- 无需本地计算

**劣势**：
- 当前 DashScope 实时 API 不支持说话人分离
- 依赖云端服务可用性
- 增加 API 调用成本

**结论**：待云端 API 支持后考虑。

## 决定

**采用「本地声纹聚类（MFCC + 余弦相似度）」方案**。

核心设计：
1. **特征提取**：每 2 秒音频提取 MFCC(12 维) + 能量(1 维) + MFCC std(1 维) = 14 维特征向量
2. **实时聚类**：余弦相似度阈值 0.70，高于阈值归入已知说话人，否则创建新说话人
3. **时间对齐**：ASR 句子根据时间戳匹配最近的声纹特征，获得说话人标签
4. **渐进式档案**：每个说话人的特征向量累积平均，提升匹配稳定性

## 后果

- 正面：零云端依赖实现实时说话人分离；轻量级实现；用户可在录音过程中看到发言人区分。
- 负面：准确率低于神经声纹模型；2-4 人场景效果较好，更多人或音色相近时可能误判。
- 后续可探索：① v2 引入 resemblyzer/WeSpeaker 提升准确率；② 待 DashScope 推出流式说话人分离 API 后切换。

## 后续演进（v4 · 2026-09-04 追加）

- **批处理侧已完成神经声纹升级**：v4 把 `core/voiceprint.py` 的编码器从 resemblyzer GE2E 升级为 CAM++（FunASR CAMPPlus，中文语料训练，192 维嵌入），判别力显著提升，清掉了 GE2E 时代的 cohort centering 补丁。详见 `CHANGELOG.md` v1.x-camplus-encoder。
- **实时侧尚未跟进**：`core/diarization.py` 仍用 MFCC 14 维特征做在线聚类（本 ADR 原方案）。ROADMAP 的 M1 项规划把实时聚类也升级到 CAM++ 192 维嵌入，复用批处理侧已集成的 encoder。
- 本 ADR 关于"v1 采用 MFCC、v2 考虑神经模型"的决策边界仍成立；v4 仅在批处理侧提前兑现了"神经模型"这条路径，实时侧仍按原计划推进。
