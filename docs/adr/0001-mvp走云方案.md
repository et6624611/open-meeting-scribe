# ADR-0001 MVP v1 走云方案，不做本地语音解析

- 状态：Accepted
- 日期：2026-09-03
- 相关：MISSION.md、docs/ARCHITECTURE.md

## 背景
原设计为本地链路：FunASR（ASR）+ pyannote（说话人分离）+ Ollama（纪要）。落地前体检发现三处阻断：
1. pyannote 是 HuggingFace **受限模型**，需网页手动同意协议，而本机 **HF token 不存在**。
2. 本机**直连 huggingface.co 超时**（被墙），无法下载 pyannote。
3. 本地链路还需 torch/pyannote/FunASR，与系统 Python 3.14 不兼容，须另建 3.11 环境，且首次下载 6–8GB 模型。

同时验证：本机**直连 dashscope.aliyuncs.com 正常**（0.1s 响应）。通义录音文件识别一个 API 即可同时做 ASR + 说话人分离。用户明确「可以上云」。

## 选项
1. **坚持本地**：解决 HF 授权 + 镜像下载 + 建 3.11 环境。优点=隐私/离线/零 API 费；缺点=麻烦、周期长、MPS 兼容与内存风险。
2. **纯云（DashScope）**：ASR+分离+纪要全走云。优点=省事、免 HF、免大模型下载、成本极低（约 0.288 元/小时）；缺点=音频上云、需联网、异步有排队延迟。
3. 云为主 + 本地兜底：v1 就要维护两套，复杂度翻倍。

## 决定
**v1 采用选项 2：纯云方案**。本地链路（选项 1）作为 v2 备选保留，不在本版实施。

## 后果
- 正面：砍掉 pyannote/FunASR/torch/Ollama/HF 授权/6–8GB 下载；依赖收敛到 requests+fastapi；P0 极轻，能快速跑通。
- 负面：音频须上云（已确认可接受）；断网不可用；出纪要有数分钟排队。
- 后续需注意：① 与 MISSION「本地数据·云端智能」定位存在偏差——已在 ADR-0015 澄清为「数据主权本地 + 计算能力云端」；② ~~涉密会议暂不适合 v1，需 v2 本地方案兜底~~ ——v2 本地方案已取消（2026-09-12），项目无离线版本开发计划，计算能力持续通过云端 API 提供。
