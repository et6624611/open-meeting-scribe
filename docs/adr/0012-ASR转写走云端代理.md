# ADR-0012：ASR 转写走云端代理，DashScope Key 不落地

- **状态**：已接受（2026-09-07）
- **关联**：ROADMAP「ASR 代理改造」

## 背景

客户端当前直连 DashScope API 进行语音转写（批处理 + 实时流式），API Key 存储在客户端 `.env` 或 `settings.json`。打包分发后 Key 随安装包暴露，且无法统一控制调用量和计费。

短信服务已完成同类改造（ADR-0010），证明代理模式可行。

## 决策

将 ASR 转写请求改为 HTTP/WebSocket 调用云端代理，代理持有 `DASHSCOPE_API_KEY` 并调用 DashScope API。客户端不再存储任何 DashScope Key。

### 通信协议

- 客户端 → 代理：HTTP POST + `X-ASR-Timestamp`（Unix 秒）和 `X-ASR-Sign`（HMAC-SHA256(token, timestamp)）
- 代理校验签名 + 时间戳（TTL 5 分钟防重放），再调用 DashScope API
- 实时流式：WebSocket 连接 `ws://proxy:8200/asr/ws`，代理做纯中继（透传 DashScope 协议）

### 端点

| 路径 | 方法 | 用途 |
|------|------|------|
| `/asr/upload` | POST | 接收音频文件，上传到 DashScope 临时存储，返回 `oss://` URL |
| `/asr/transcribe` | POST | 提交批处理转写 + 内部轮询 + 返回完整结果（含说话人分离） |
| `/asr/ws` | WebSocket | 实时流式转写中继（客户端 ↔ 代理 ↔ DashScope） |
| `/health` | GET | 健康检查 |

### 环境变量变更

客户端新增：
- `ASR_PROXY_URL`（默认值通过环境变量配置）
- `ASR_PROXY_TOKEN`（共享密钥，与代理端一致）

客户端移除：
- `DASHSCOPE_API_KEY`（客户端不再直连 DashScope）
- 设置页的 ASR API Key 配置入口

服务端（asr-proxy）：
- `ASR_PROXY_TOKEN`（与客户端一致）
- `DASHSCOPE_API_KEY`（平台 Key，仅服务端持有）

## 后果

- **正面**：DashScope Key 不再随安装包分发，客户端无法绕过代理直接调用；计量逻辑简化为始终计量（无"自带 Key"分支）
- **负面**：ASR 功能依赖代理服务器可用性；批处理转写延迟略增（多一跳代理轮询）；实时流式增加代理层 WebSocket 中继复杂度
- **代理端已实现**：`asr-proxy/` 目录包含完整 FastAPI 服务，含签名校验、DashScope API 调用、WebSocket 中继、systemd 部署脚本
