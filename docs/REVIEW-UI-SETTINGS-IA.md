# UI-REVIEW-SETTINGS-IA-01

## 背景（一段话）

设置页现状被诊断为「一个逻辑状态（access_mode）暴露成四个可写面 + 界面语言未与实现模型解耦」。2026-09-26 项目方已裁两条结构决定：**① 云端声纹下架，声纹仅本机 CAM++；② 体验/托管不再独立成卡，决策层收敛为「离线 / 联网」两卡，体验配额降为账户登录门后的 ASR/LLM 能力级算力来源选项，账户「优先使用体验」勾选决定详情默认生效值**。需求单将在本评审通过后拆分登记（REQ-SETTINGS-IA 止血单 + REQ-EXPERT-MODE 专家详情单）。

## 评审对象（全部在 main 工作区，未提交 git 的评审态文件）

1. **可交互对照原型**（主对象）：`docs/prototypes/PROTOTYPE-SETTINGS-IA.html` — 浏览器直接打开。三视图：
   - ① 现状·哪里乱：双写保存语义冲突模拟器、静态隐私承诺矛盾演示、三套词汇对照表、专家模式形态问题；
   - ② 配置明细下钻：L0 套餐 → L1 LLM（含 provider 预设/本机端点探测）→ L2 ASR → L3 本地引擎资产 → L4 CLI 引擎 → L5 对话面板；
   - ③ 建议：两卡决策层 + 能力级详情层可点演示（含后果预览、默认生效徽章、配额耗尽明示降级、矩阵按能力逐行高亮）。
2. 现状需求依据：`docs/REQUIREMENT-ACCESS-MODE-CARDS.md` §1（诊断同源）。
3. 真实代码参照：`frontend/src/views/SettingsView.vue`、`frontend/src/components/settings/AccessModeCards.vue`（原型中所有行号引用可回查）。

## 请审查什么（按优先级）

| # | 审查项 | 关注点 |
|---|---|---|
| R1 | ③ 两卡 + 六卡详情栅格的层级与密度 | 「账户勾选→详情默认生效」的因果联动在视觉上如何表达（现仅徽章）；离线模式下详情置灰只读的 affordance 是否够清楚 |
| R2 | 能力级算力来源选择器（LLM/ASR 各一） | 选项命名（体验配额/自带 Key/本机端点）+ 就绪态/警告态的行内呈现；与「服务」编辑面（L2）的空间关系 |
| R3 | 专家详情 = 注释层的视觉语法 | `engine.mode=…` 技术注释、矩阵技术列名以何种样式叠加，保证「同模型加细节」而非「换了一套界面」的感知 |
| R4 | 后果预览弹窗（卡片切换） | 信息结构（将改写投影字段/进程动作/计费提示）与确认节奏；对照 ① 页现状「一次点击全改」的反差是否有说服力 |
| R5 | ① 页诊断叙事的呈现质量 | 作为评审会演示动线（现状→下钻→建议）是否顺畅，有无更直观的冲突表达方式 |
| R6 | 词汇收敛落地检查 | 全局仅 离线/联网/体验配额/自带 Key 四词；你方对「联网模式」定名（原型 Q1）有无更优候选 |
