# REQUIREMENT-AI-NATIVE-OUTPUT-STRUCTURE — 会议产出资料的 AI 原生渐进式存储结构

- **需求编号**: REQ-OUT-STRUCT-1
- **状态**: 可排期（2026-09-24 项目方确认 R2 取舍：目录用稳定 ID、显示名进索引元数据，Agent 友好优先）
- **优先级依据**: 影响产品核心定位（AI 原生、Agent 可消费）；不阻塞当前发布；改造涉及存量迁移，成本中等偏高
- **分类**: 产品架构 / 数据组织
- **Owner**: 产品经理（本单）；实施预计派后端（存储链路）+ 前端（路径适配）
- **来源**: 2026-09-24 用户反馈批次 D1，访谈三决策点已由项目方确认：①按知识库-会议分目录；②分层索引；③消费方以 Agent 为主

## 1. 问题

当前会议产出全部平铺在 `data/output/`：实测 178 个文件，命名为 `<hash8>_<时间戳>_纪要.md`，同一会议因重新生成产生多个近似重复版本，无层级、无索引、无元数据。后果：

- Agent 无法按「知识库 → 会议 → 内容层」逐层下钻定位，只能全量扫文件名；
- 人类用户不可读、不可浏览，产出资料事实上成为"只写不读"的暗数据；
- 与产品「关联知识库 / 项目」的既有概念脱节——UI 里有知识库，落盘结构里没有。

## 2. 目标用户与场景

- **主：Agent（会议助手、外部 AI 工具）**——回答跨会议问题时需要：读根索引 → 选知识库 → 选会议 → 只加载所需内容层（渐进式披露），避免一次性吞全量原文。
- **次：人类用户**——在文件管理器/编辑器中直接浏览时，目录名即知识库名、会议名，可定位。

## 3. 目标结构（方案骨架）

```
data/output/
  index.json                      # L0：全局索引（schema_version、知识库清单、生成时间）
  <kb-id>/                        # L1：按知识库/项目分目录，目录名=稳定 ID；显示名只存索引
    index.json                    # 该库会议清单：meeting_id、标题（当前显示名）、日期、参会人数、一句话摘要、内容层清单
    <meeting-id>/                 # L2：一会议一目录，目录名=稳定 ID；标题/日期等进 manifest
      manifest.json               # 会议元数据：kb、标题、日期、说话人映射、版本链、内容层相对路径
      summary.md                  # L3：纪要（当前定稿版）
      chapters.md                 # L3：章节/要点
      decisions.md                # L3：决策与待办
      transcript.md               # L4：转写原文（含句级时间戳）
      insights/                   # 洞察台产物（图表描述、分析记录）
      archive/                    # 历史重新生成版本（只保最新为定稿，旧版下沉）
```

关键设计约束：
1. **渐进式披露**：每层 index/manifest 自足——Agent 读上一层即可决定下一层是否加载，任何一层不需要全量加载同层其他文件。
2. **机器优先、人类可读（R2 已裁决）**：目录名一律用稳定 ID，知识库/会议显示名与改名只落 JSON 索引与 manifest，改名不搬目录；人类浏览时经 UI 或索引对照显示名。
3. **重新生成语义**：定稿唯一（当前版在位），历史版本进 `archive/`，manifest 记录版本链——消除现状的多副本平铺。
4. **未关联知识库的会议**归入 `_unassigned/`，不阻塞生成。

## 4. 非目标

- 不改变纪要/转写的生成链路与内容格式（本次只动"放到哪、怎么索引"）。
- 不做云端同步结构 / 多端合并策略。
- 不引入数据库存储；保持文件系统即真相源。
- 录音原始文件（`data/recordings/`）本次不动，仅在 manifest 中引用相对路径。

## 5. 验收标准（初稿，排期前与后端细化）

- AC-1 新会议完成后，产出按上述结构落盘，`index.json`/`manifest.json` 可被 `json.load` 且字段完整。
- AC-2 Agent 场景走查：给定"某知识库近 7 天会议的决策汇总"任务，仅通过逐层读取 index 即可定位全部所需文件，无需目录级全量扫描。
- AC-3 同一会议重新生成 N 次后，定稿目录只有一份当前版，旧版在 `archive/` 且 manifest 版本链正确。
- AC-4 存量迁移脚本：现有 178 个文件按会议前缀归并到新结构，无法归类的进 `_legacy/`，迁移有 dry-run 与报告。
- AC-5 现有 UI（纪要页、洞察台、导出）读取路径适配新结构，回归通过。
