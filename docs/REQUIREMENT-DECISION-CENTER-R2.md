# 需求记录：决策中心使用反馈迭代（REQ-DECISION-CENTER-R2）

## 1. 背景与证据核验

决策中心（DC-DEC-B1/F1）2026-09-25 项目方浏览器点验通过后，项目方提出五条使用意见 + 一条冗余观察。管理员逐条对照 main 代码核实（行号已确认）：

| # | 项目方反馈 | 代码证据 | 核验结论 |
|---|---|---|---|
| 0 | 分组视图下卡片底部重复显示会议名称，信息冗余 | 组头已显示会议标题（`DecisionCenterView.vue:82`），卡片 meta 行又显示来源会议标题+日期+知识库（`DecisionCard.vue:29-41`） | **属实**，组内卡片「来源会议」文本冗余 |
| 1 | 应支持在决策中心内直接操作，避免跳转至会议纪要才能修改 | 卡片操作菜单仅「已被取代/已撤销」两项（`DecisionCard.vue:17-24`），**无编辑文本、无删除** | **属实**；已裁决范围=编辑+删除（§11-D1） |
| 2 | 平铺与按会议分组无明显视觉区分，平铺失去意义 | 切换器存在（`DecisionCenterView.vue:12-15`）；两视图卡片同款，差异仅组头折叠条 | **属实**，移除切换 |
| 3 | 补录弹框输入内容与会议纪要需输入的内容不一致 | 弹框现状 = 归属会议+单条决策文本+待确认勾选（`AddDecisionDialog.vue:13-35`） | **已裁决**（§11-D2）：决策条目应含**标题、内容、执行人**三要素；现模型只有 `text` 单字段，无标题/执行人（`core/summarize.py:561-570` 解析产物）→ 派生 O4 |
| 4 | 筛选中的知识库未支持检索 | 知识库筛选为原生 `<select>`（`DecisionCenterView.vue:32-36`），无输入过滤 | **属实**，升级可检索 |
| 5 | 状态能否自定义：改写名称、新增状态、排序、颜色标注 | 状态为封闭枚举 `active/superseded/revoked` + `pending` 标志 | **已裁决**（§11-D3）：一步做全量自定义 → 派生 O5（语义锚点绑定规则） |

## 2. 目标

按项目方反馈与裁决迭代决策中心：**去冗余、免跳转编辑、去无效切换、决策三要素化、知识库可检索、状态全量可自定义**。

## 3. 交付项

### F1 — 分组卡片去冗余（approved，无争议）

- 分组视图组内卡片 meta 行不再显示来源会议标题文字；跳转纪要能力保留（图标/悬停，随视觉稿定）；日期/知识库徽标保留与否随实施稿。

### F2 — 移除「平铺/分组」切换（approved，无争议）

- 删除视图切换器（`dc-seg`），固定按会议分组；`view_flat` i18n 键与代码清理。

### F3 — 决策中心行内编辑与删除（approved，范围=裁决 D1）

- 卡片操作菜单新增**编辑决策文本**、**删除决策**。
- 走既有任务级 CRUD API（`PUT/DELETE /api/tasks/{task_id}/decisions/{id}`），无新接口。
- 编辑/删除**不回写纪要正文**（与 REQ-DECISION-CENTER §11-3 同构）。
- 注：与 F4 联动——三要素落模型后，行内编辑升级为编辑三字段（见 O4 结论）。

### F4 — 决策条目三要素化（approved，口径随 §11-D4/D5 定稿）

- 补录弹框字段：归属会议 + **标题** + **内容** + **执行人**；`[待确认]` 勾选维持现状（标志位，不并入状态字典，见 D7）。
- **实施口径（09-25 定稿）**：
  1. 数据模型：`decisions[]` 新增 `title`、`owner_id`（说话人档案 uuid）、`owner_name`（展示快照/兜底）；`text` 语义收窄为「内容」。
  2. **执行人 = 选人不选文本**（D4）：弹框内执行人控件为可搜索的说话人档案下拉（`data/speakers.json` 现 32 档）；**档案里没有的人可直接手打并即时建档**（不跳页、不断流）。读取侧以 `owner_id` → 档案名为权威，档案被删或查不到时回退 `owner_name` 快照——**改名全局跟随，不需批量重写存量任务 JSON**。
  3. **AI 生成决策只要求标题 + 正文**（D5）：纪要「主要结论」章节 prompt 契约改为两要素条目式（`**标题**：正文`），解析器 `parse_decisions_from_summary()` 随改；owner 对 auto 决策**不作要求、合法留空**。
  4. 存量 359 条无 `title` 的决策：读取侧降级——卡片标题取内容首句截断展示，不报错、不批量改写落盘文件。
  5. 决策卡片、聚合 API、`docs/API_CONTRACTS.md` §12 契约随改。
- **已接受的代价**（项目方知情）：纪要正文形态由叙事段落变为条目式「标题：正文」，属 D5 明确许可。

### F5 — 知识库筛选支持检索（approved，无争议）

- `<select>` 升级为可输入过滤 combobox；保留「全部 / 未归属」特殊项。

### F6 — 决策状态全量自定义（approved，口径随 §11-D6/D7 定稿）

- 功能承诺：用户可**改写状态显示名、新增状态、删除自定义状态、排序、逐状态颜色标注**。
- **系统锚点收敛为两个**（D6，项目方明确选择）：`active`（生效中，新决策默认态）与 `done`（完成，唯一保底闭档态），二者不可改名、不可删除。
- **「已被取代」「已撤销」从系统状态降级**（D6）：
  1. 决策卡片菜单的「已被取代 / 已撤销」两个入口**移除**，`SupersedeDialog.vue` 与 supersede/revoke 写回端点下线（项目方知情：这是删除已点验上线的能力）。
  2. 迁移：存量 `status=superseded/revoked` 的决策落到迁移时自动创建的**两个普通自定义状态**（默认名「已被取代」「已撤销」、默认闭档=是），历史语义不丢、日后可编辑可删除。
  3. `superseded_by` 字段停止写入，存量数据保留只读展示（不崩旧卡片）。
- **自定义状态语义**（D7）：状态字典条目携带 `closing` 布尔（是否算「完成类」）——闭档状态在默认视图隐藏并沉底；新增状态默认 `closing=false`（普通可见态）；默认筛选 = 全部非闭档状态，「查看全部」可放开。`pending_confirmation` 维持标志位不并入字典。
- 实施面：聚合 API `status(s)`/`statuses` 参数与 pydantic 校验按字典改造、`docs/API_CONTRACTS.md` §12 重写；前端筛选 chips / 徽标 / 沉底 / 颜色 token 全部配置驱动；新增状态管理设置界面；既有 AC 7 项与 DC 两单已验收行为需重新回归。

3. 决策卡片菜单可编辑文本并可删除；删除的 `auto` 决策在重新生成纪要后不复活。
   > **09-25 产品注记**：后半句经 DC-R2-a 验收核实为前端不可达（main 合并函数无墓碑，删除的 auto 决策重生成必复活），已拆派生单 DC-R2-BE（待派工队列）；DC-R2-a 前端半句（编辑+删除+二次确认）验收通过，后半句随 BE 单闭环或项目方豁免。

5. （F4）补录弹框含标题/内容/执行人字段，执行人为说话人档案选人控件且支持手打即时建档；AI 生成的决策带标题+正文（owner 可空）；存量无标题决策降级显示不报错；纪要「主要结论」呈条目式。
6. （F6）状态设置界面可改名/新增/排序/标色，新状态可勾选「算完成类」；默认视图只现非闭档状态且可切「查看全部」；「生效中/完成」两个锚点不可改名不可删；卡片菜单不再出现「已被取代/已撤销」，存量这两种状态经迁移后语义与徽标不丢。

## 11. 裁决记录（项目方，2026-09-25，AskUserQuestion 批复）

- **D1**（原 O2）：决策中心内直接操作范围 = **编辑 + 删除决策条目**；查看纪要保留跳转。
- **D2**（原 O1）：补录不一致点 = 项目方心智中决策条目含**标题、内容、执行人**（对齐纪要决策），现弹框仅单文本 → F4 按三要素方向，派生 O4。
- **D3**（原 O3）：状态自定义采**一步全量**（改名+新增+排序+颜色全做）→ F6 按方案乙，派生 O5。

### 二轮裁决（项目方，2026-09-25，O4/O5 关闭）

- **D4**（O4-①，执行人形态）：**不用自由文本，改为选说话人档案**；弹框内可直接手打人名并即时建档（采纳实施方推荐项）。落库 `owner_id` 为权威 + `owner_name` 快照兜底，改名全局跟随。
- **D5**（O4-②，AI 侧范围与纪要形态）：**AI 生成的决策只要有标题 + 正文，其余（含执行人）不作要求** → 纪要「主要结论」接受改为两要素条目式模板。
- **D6**（O5-①②，系统锚点与取代/撤销去留）：**只固定「完成」为系统级保底选项，其余全部由用户定义**；项目方在三个选项中明确选择「只留完成，砍掉这两项」——即**「已被取代」「已撤销」两个卡片菜单入口与对应系统状态一并移除**（知情：此为删除已上线能力）。实施以存量迁移（自动创建两个可删自定义状态）保证历史数据语义不丢，属实施方为数据诚实追加的兜底，未扩大功能面。
- **D7**（O5-③④，默认筛选与待确认）：过滤规则 = **默认视图只看「非完成类」，用户可查看全部**；新自定义状态由用户**逐项勾选是否算完成类（`closing`）**（采纳推荐项）；`[待确认]` 维持标志位不并入字典（采纳实施方建议，项目方未异议）。
