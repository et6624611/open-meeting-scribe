# 需求记录：本地可选计算引擎（离线模式）

## 项目方决策记录（2026-09-23，决策人：Yongliang Wang）

| # | 裁决 | 影响 |
|---|------|------|
| D1 | MVP 收敛为**落地本地 ASR**；LLM 侧不托管本地大模型，仅支持用户自接 **Ollama / LM Studio 等 OpenAI 兼容端点** | 采纳 P1 折中；LLM 云默认仍为 qwen-plus（ADR-0003 不动） |
| D2 | **声纹离线化**：离线模式下声纹注册与匹配回归本地 CAM++，不依赖 voiceprint-service 云服务 | **部分修订 ADR-0009**；已立 [ADR-0018](adr/0018-本地可选计算引擎与声纹离线化.md)（Proposed） |
| D3 | **排期：P0 级开发内容，立即进入开发队列**（不等当前批次功能收尾） | 本需求升格为最高优先级；需进 ROADMAP 主线并让渡当前迭代容量 |

D2 的内在逻辑：ADR-0009 拆分的首要动机是裁掉 torch（~543MB）以缩减包体；而 D1 的本地 ASR（FunASR）必然引入 torch，torch 成为离线模式的沉没成本，拆分动机在离线场景不再成立。且声纹注册表当时已设计为云端 `cam++-v1-cloud` 与本地 `cam++-v1` 互相兼容（ADR-0009），离线化迁移成本低。

## 问题陈述

1. **合规叙事漏洞**：[ADR-0015](adr/0015-本地优先原则重定义与引流授权服务.md) 定义「本地数据·云端智能」，关键约束是"用户业务数据永不落地到项目方服务器"。但现状下**录音音频仍需上传**至 DashScope / asr-proxy / voiceprint-service 完成转写与声纹比对——对涉密会议（法务、财务、人事、涉密研发）用户，数据事实上出设备。
2. **开源采用天花板**：竞品调研（2026-09-23 实测）显示品类第一心智已被 Meetily（31k★）锁定为「100% 本地、零云依赖」；本项目 ASR/LLM 云依赖 + 需注册阿里云获取 Key，直接否决英文区主流用户，全球星数预期从 5k–10k 级压到 500 级。
3. **无 Key 启动门槛**：新用户下载后须先配置 `DASHSCOPE_API_KEY`（或注册项目方体验授权）才能跑通核心链路，挫伤 GitHub 场景「clone 即试」的转化。

## 与既有决策的关系（不冲突声明）

- **不改写 ADR-0015 原则**：本需求是在计算能力层新增**可选**引擎，云端引擎仍是默认路径；「数据主权本地」由"存储层本地"升级为"存储+计算均可本地"，属于兑现并强化该原则，不是推翻。
- **不改写 ADR-0001/0002/0003**（云方案选型）：那些决策针对 v1 MVP 速度目标，本需求是存量决策的 v2 方向兑现（MVP_PLAN 曾预留「FunASR + pyannote + Ollama 作为 v2 备选」）。
- **LICENSE 维持 AGPLv3**（ADR-0016 已决策，本需求不重提许可证议题）。
- **体验授权漏斗不受损**：离线模式反而提供「零配置起步 → 云端引擎提质 → 注册体验授权」的新漏斗入口。
- **与 ROADMAP v2「本地兜底」的关系**：v2 已收窄为"本地仅录音落盘、联网后再识别"。本需求是超出 v2 的独立能力，建议作为新版本节点（如 v8）进入 ROADMAP 主线，**版本排期待项目方决策**。

## 目标用户

| 段 | 痛点 | 本需求价值 |
|---|---|---|
| 涉密行业会议用户（法务/财务/政企） | 录音不得出内网 | 唯一可行路径 |
| 国际个人开发者/隐私敏感用户 | 不愿注册阿里云 | 零云依赖可用 |
| 内网/离线环境用户 | 无公网出口 | 断网可用 |
| GitHub 首次访问者 | 配 Key 劝退 | 下载即跑通 |

## 典型场景

1. 用户在「设置 → 计算引擎」选择「本地优先」，首次触发模型下载（带进度、断点续传、可取消）。
2. 完全断网环境下：录音（麦克风/系统内录）→ FunASR 离线转写 + 本地说话人分离 → 本地 CAM++ 声纹姓名化 → 用户自接 LLM 端点生成结构化纪要（结论/行动项）→ 导出。
3. 混合模式：离线完成的录音，联网后可一键用云端 paraformer-v2 重转写以获得更高精度（保留既有"云端提质"心智）。

## 范围（MVP 建议）

- **可插拔 ASR Provider**：现 DashScope 抽象之外新增本地引擎（FunASR paraformer 离线模型 + 本地说话人分离）；统一转写结果契约（对齐 `docs/API_CONTRACTS.md`）。
- **LLM 自接端点（依 D1）**：设置支持配置 OpenAI 兼容端点（base_url / model / 可选 key），提供 Ollama、LM Studio 预设与连通性测试；**不含**本地大模型的安装托管。复用现有纪要提示词管线，并针对小模型做防幻觉约束调优。
- **声纹离线化（依 D2）**：离线模式下声纹注册与批处理匹配回归本地 CAM++（28MB 权重，ModelScope `iic/speech_campplus_sv_zh-cn_16k-common`），与本地 ASR、本地分离构成断网闭环；注册表与云端 `cam++-v1-cloud` 保持既有的双向兼容设计。
- **模型资产管理**：下载、校验、存储位置配置、容量提示、离线安装（内网用户人工拷贝模型包）。
- **UI 透明性**：全局引擎状态标识（本地/代理/自持 Key），数据处理流向说明。
- **打包分发**：macOS / Windows 桌面端附带引擎选择首启流程；主安装包不内置大模型。

## 非目标（Non-Goals）

- 不做端侧训练/微调。
- 不追求实时流式转写在低端 CPU 上达到云端同级体验（实时链路可先限定"本地引擎降级为分段批处理"，显性声明）。
- 云端模式声纹不在本需求范围（维持 voiceprint-service 走云，ADR-0009 对云模式继续有效；离线化范围见 ADR-0018）。
- 不自动安装/托管本地大模型与 Ollama 本体（依 D1，用户自装自配）。
- 不在本需求内做 GGUF 量化调优/多硬件加速矩阵（CUDA/MPS 优化只保 Apple Silicon + CPU 基线）。
- 不改变默认引擎（默认仍云端，本地为显式选择）。

## 验收标准

1. **断网闭环**：拔掉网线，在 macOS 与 Windows 各完成一次「录音 → 转写 → 说话人分离 → 声纹姓名化 → 纪要（用户自接本地 LLM 端点）→ 导出 docx/md」全流程，除 localhost（用户自装的 Ollama 等）外零网络请求（代理抓包验证白名单外域名零命中）。
2. **质量门槛**：用 `samples/` 中 ≥3 段真实中文会议录音（2/4/6 人），本地引擎字错误率与云端 paraformer-v2 差距 ≤15% 相对值；纪要含结论与行动项的可用性评分（内部评审）≥ 云端的"可接受"档。
3. **资源门槛**：Apple Silicon 16GB / Windows 16GB 内存机型上，转写 30 分钟会议峰值内存 ≤8GB（明确标注）；模型总下载体积 ≤X GB（X 由工程评审定，建议 ≤3）。
4. **可回退**：任一本地引擎失败自动/手动切回云端，任务状态不丢失。
5. **合规标注**：README/SECURITY.md 更新数据处理流向矩阵，三种引擎（本地/体验代理/自持 Key）各自的数据边界一屏可查。
6. **声纹注册表兼容**（依 D2）：云端模式（`cam++-v1-cloud`）与本地模式（`cam++-v1`）间，同一批注册数据无需迁移即可直接使用；对同一组说话人抽查两侧匹配结果一致性（本地侧误识率相对云侧差异 ≤5%）。

## 依赖与风险

| 项 | 说明 | 缓解 |
|---|---|---|
| FunASR 模型许可证 | ModelScope 权重各有许可条款，需逐模型核查可否随 AGPL 分发/引导下载 | 采用"引导下载"而非内置分发；THIRD_PARTY_NOTICES 增补 |
| 本地小模型纪要质量 | qwen2.5:7b 级别模型中文纪要与 qwen-plus 有可感知差距 | 提供"联网提质"回云路径；提示词针对小模型专门调优 |
| 实时转写 CPU 负载 | paraformer streaming 在低配机上可能卡顿 | MVP 声明本地模式实时链路降级为分段批处理 |
| 热词能力差异 | 云端热词加权在本地引擎无对等能力 | 显性文档说明差距；后处理替换作为过渡方案评估 |
| 打包复杂度 | PyInstaller + torch/funasr 依赖膨胀，双平台构建时长增加 | 本地引擎做成可选组件/插件安装，不进主包 |
| torch 回归主项目 | FunASR + 本地 CAM++ 使 ADR-0009 的包体缩减成果在本地组件内失效（torch ~543MB） | 仅在本地引擎组件引入 torch，云端模式安装包保持精简；两套分发物在文档中明确规格差异 |
| 说话人分离精度 | 本项目 BACKLOG 已记录分离质量痛点，本地侧更弱 | 与 BACKLOG「说话人分离优化」条目合并跟踪，手动修正入口作为体验补偿 |

## 度量（发布后验证假设）

- 本地引擎激活用户占比；模型下载完成率。
- 本地 vs 云端引擎的纪要重生成率（用户对结果不满足而回云的比例）。
- GitHub Star 增长与 README「offline」关键词进入路径——验证"离线能力驱动采用"假设。
